上回说到：`/users/{user_id}` 里的 `user_id` 是**路径参数**，它嵌在 URL 路径里，标识"哪个资源"；而 `?page=1` 这种挂在路径后面的 `?键=值` 是接下来要讲的 **查询参数（query parameter）**。路径参数从 URL 路径取数，查询参数从 `?` 后面的查询字符串取数。常出现在列表、筛选、分页这类常见的接口

## Part 1 类型与默认值：声明类型即自动校验

**只要函数参数不是路径参数，FastAPI 就自动把它当成查询参数**——这是查询参数的第一条规则。先用一份内存数据库做例子，模拟"跳过前几条、最多取几条"的分页：

```python
fake_items_db = [{"item_name": "Foo"}, {"item_name": "Bar"}, {"item_name": "Baz"}]

@app.get("/items/")
async def read_item(skip: int = 0, limit: int = 10):
    return fake_items_db[skip : skip + limit]
```

访问 http://127.0.0.1:8000/items/?skip=0&limit=10：

```json
[{"item_name": "Foo"}, {"item_name": "Bar"}, {"item_name": "Baz"}]
```

URL 里 `?` 之后的部分就是**查询字符串（query string）**，是一组用 `&` 分隔的 `键=值` 对，上面这个 URL 里有两个查询参数：`skip=0` 和 `limit=10`。因为是 URL 的一部分，这些值"天生"是字符串；但一旦声明了类型（这里是 `int`），FastAPI 就会把它们转换成整数并校验，再把 `skip=0`、`limit=10` 传进函数。

查询参数不是路径的固定组成部分，所以**可以带默认值**。上面的 `skip=0`、`limit=10` 就是默认值。于是访问不写查询参数的 http://127.0.0.1:8000/items/，效果等价于访问 `?skip=0&limit=10`

示例：

| 访问的 URL                   | skip 的值 | limit 的值 |
| -------------------------- | ------- | -------- |
| `/items/`                  | `0`（默认值） | `10`（默认值） |
| `/items/?skip=20`          | `20`    | `10`（默认值） |

即对于没有传入的参数，会使用默认值

## Part 2 可选参数：默认值为 None 就是可填可不填

当我们想让一个查询参数在使用时选用（即使不传入也不调用默认值），我们可以把默认值声明为 **None**：

```python
@app.get("/items/{item_id}")
async def read_item(item_id: str, q: str | None = None):
    if q:
        return {"item_id": item_id, "q": q}
    return {"item_id": item_id}
```

这里的 `q` 是可选查询参数，默认值是 `None`。函数内部用 `if q:` 判断：传了 `q` 就把它带进返回值，没传就只回 `item_id`。请求 `/items/foo` 返回：

```json
{"item_id": "foo"}
```

请求 `/items/foo?q=bar` 返回：

```json
{"item_id": "foo", "q": "bar"}
```

## Part 3 类型转换：bool 的一堆"真"

查询参数能转换的类型不止 `int`、`str`，`bool` 也有一套专门规则。改造一下例子：`short` 声明成 `bool`，默认 `False`，用来控制是否输出"简短版本"：

```python
@app.get("/items/{item_id}")
async def read_item(item_id: str, q: str | None = None, short: bool = False):
    item = {"item_id": item_id}
    if q:
        item.update({"q": q})
    if not short:
        item.update(
            {"description": "This is an amazing item that has a long description"}
        )
    return item
```

请求 `/items/foo?short=1`、`?short=True`、`?short=true`、`?short=on`、`?short=yes`——这些写法**统统**都会让函数里的 `short` 变成 `True`，换成大小写混合（全大写、首字母大写等）也一样。规则是：

| URL 里的写法                  | 函数里 short 的值 |
| -------------------------- | ------------- |
| `1`、`True`、`true`、`on`、`yes`（及任意大小写变体） | `True`        |
| 其他写法（如 `0`、`no`、`off`）      | `False`       |

## Part 4 多个路径参数、查询参数叠加

把分页、过滤和路径参数全凑到一起，就能看出 FastAPI 的"嵌套解析"能力：**一个函数里可以同时声明多个路径参数和多个查询参数，不用管声明顺序，FastAPI 按参数名识别，知道哪个值该进哪个参数**：

```python
@app.get("/users/{user_id}/items/{item_id}")
async def read_user_item(
    user_id: int, item_id: str, q: str | None = None, short: bool = False
):
    item = {"item_id": item_id, "owner_id": user_id}
    if q:
        item.update({"q": q})
    if not short:
        item.update(
            {"description": "This is an amazing item that has a long description"}
        )
    return item
```

这个接口里有两种参数叠在一起：

| 参数名    | 类型            | 类别   | 从哪来                     |
| ------- | ------------- | ---- | ----------------------- |
| `user_id` | `int`         | 路径参数 | `/users/{user_id}` 占位符    |
| `item_id` | `str`         | 路径参数 | `/items/{item_id}` 占位符    |
| `q`      | `str \| None` | 查询参数 | `?q=...`                |
| `short`  | `bool`        | 查询参数 | `?short=...`             |

请求 http://127.0.0.1:8000/users/2/items/foo?q=hi&short=1，函数收到的参数是：`user_id=2`（整数）、`item_id="foo"`、`q="hi"`、`short=True`。路径参数和查询参数混在同一份函数签名里

## Part 5 必选查询参数：不写默认值即为必选

URL 里少了路径，接口根本匹配不上，所以路径参数是必选的；而查询参数则默认可选。但想让它必选也很简单：**不写默认值**。`needy` 声明成 `str` 且不给默认值，它就是必选查询参数：

```python
@app.get("/items/{item_id}")
async def read_user_item(item_id: str, needy: str):
    item = {"item_id": item_id, "needy": needy}
    return item
```

直接访问 http://127.0.0.1:8000/items/foo-item、不带 `needy`，FastAPI 会返回 422 校验错误：

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["query", "needy"],
      "msg": "Field required",
      "input": null
    }
  ]
}
```

错误信息里 `loc` 是 `["query", "needy"]`，直接指出**缺的是查询参数 `needy`**——和路径参数篇看到的 422 是同一套格式，Pydantic 依然在后面把关。带上它请求 `/items/foo-item?needy=sooooneedy` 就正常了：

```json
{
  "item_id": "foo-item",
  "needy": "sooooneedy"
}
```

一个函数里当然也可以必选、带默认值、完全可选三种参数混合：

```python
@app.get("/items/{item_id}")
async def read_user_item(
    item_id: str, needy: str, skip: int = 0, limit: int | None = None
):
    item = {"item_id": item_id, "needy": needy, "skip": skip, "limit": limit}
    return item
```

这里三个查询参数各代表一种情况：

| 参数名   | 声明方式                | 是否必选   |
| ------ | ------------------- | ------ |
| `needy` | `str`，不写默认值         | 必选，不传就 422 |
| `skip`  | `int = 0`，带默认值      | 可省略，用默认值  |
| `limit` | `int \| None = None` | 完全可选，默认 `None` |

规则总结成一句话：**查询参数写默认值 → 可选，写 `None` → 显式可选，什么都不写 → 必选**。另外，路径参数篇用 Enum 限定取值那套，查询参数同样适用

## 小结

| 概念        | 一句话                                                       |
| --------- | --------------------------------------------------------- |
| 查询参数      | `?` 之后、`&` 分隔的 `键=值` 对；非路径参数的函数参数自动按查询参数处理                 |
| 类型与默认值   | 声明 `: int` 等类型即自动解析、校验，和路径参数走同一套流程；不传时用默认值                 |
| 可选参数      | 默认值设 `None` 即完全可选，函数里拿到 `None`                            |
| bool 转换  | `1`、`true`、`on`、`yes` 及任意大小写变体 → `True`，其余 → `False`     |
| 参数叠加      | 多个路径参数和查询参数可混在同一函数里，按名字区分、无需特定顺序，"嵌套解析"各归各位          |
| 必选查询参数    | 不写默认值即为必选，缺了返回 422，`loc` 会指明是哪个查询参数                     |

## Part 1 所有权作为内存安全的规范

**所有权**（ownership）是 Rust 确保内存安全的核心机制。它的目标是：在编译期防止**未定义行为**（undefined behavior），尤其是与内存相关的错误——如使用已释放的内存、重复释放、数据竞争等

Rust 不使用垃圾回收器，而是通过所有权规则在编译时自动管理内存：每个值有且只有一个所有者，所有者离开作用域时值被自动释放

### 1.1 栈帧（Stack Frame）

函数调用时，Rust 会为该函数创建一个**栈帧**（stack frame），将局部变量存放在其中。函数返回时，栈帧被弹出，其中的变量随之释放

```rust
fn plus_one(x: i32) -> i32 {
    x + 1
}

fn main() {
    let n = 5;               // L1
    let y = plus_one(n);     // L2
                             // L3
}
```

执行过程中栈帧的变化：

| 时刻                | 栈                                |
| ------------------- | --------------------------------- |
| L1：`let n = 5`     | `main: n = 5`                     |
| L2：进入 `plus_one` | `main: n = 5` → `plus_one: x = 5` |
| L3：`plus_one` 返回 | `main: n = 5, y = 6`              |

`plus_one` 返回后，它的栈帧被弹出，`x` 不再存在。`n` 的值被复制给了 `x`，所以 `n` 不受影响

### 1.2 Box 与堆分配

对于简单的整数、布尔等固定大小的数据，复制成本很低，Rust 直接在栈上复制。但当数据体积很大时（如百万元素的数组），复制的代价不可接受。此时需要使用 **`Box`** 将数据放在**堆**（heap）上

```rust
fn main() {
    let a = Box::new([0; 1_000_000]);
    let b = a;
}
```

`a` 的值是一个**指针**，指向堆上的数组。`let b = a` 只复制了指针，没有复制数组本身。但此时 `a` 已经被**移动**（moved）——它的所有权转移到了 `b`，`a` 不再有效

> 补充：这个设计避免了"同一块堆内存有两个所有者"的情况。如果两个变量都能释放同一块内存，就会导致**重复释放**（double free），这是一种未定义行为

### 1.3 移动（Move）

对于堆上数据，赋值和函数传参都会发生**移动**。移动后原变量失效，不能再使用：

```rust
let s1 = String::from("hello");
let s2 = s1;              // s1 的所有权移动到 s2
// println!("{s1}");       // 编译错误：value used after move
```

如果尝试在移动后使用 `s1`，编译器会拒绝编译：

```text
error[E0382]: borrow of moved value: `s1`
```

这就是所有权规则在起作用——移动后原变量不再拥有数据，使用它会导致未定义行为

> 补充：对于实现了 `Copy` trait 的类型（如 `i32`、`bool`、`f64`），赋值时会发生**复制**而非移动，原变量仍然有效

## Part 2 引用和借用

移动虽然安全，但使用起来不够方便——如果每次调用函数都要转移所有权，函数结束后原变量就失效了。**引用**（reference）提供了一种不转移所有权就能访问数据的方式

### 2.1 引用传参

```rust
fn greet(name: &String) {
    println!("hello, {name}");
}

fn main() {
    let m1 = String::from("hello");
    greet(&m1);           // 借用 m1，不转移所有权
    println!("{m1}");     // m1 仍然有效
}
```

`&m1` 创建了一个**引用**，类型为 `&String`，表示"对 `String` 的借用"。引用不拥有数据，因此函数返回后不会释放堆内存

> 补充：类比：Rust 的 `&T` 类似 C++ 的 `const T&`（不可变引用），`&mut T` 类似 `T&`（可变引用）。但 Rust 的引用更严格——编译器会在编译期保证引用的安全性，而 C++ 允许写出悬垂引用等未定义行为

### 2.2 解引用

使用 `*` 运算符可以**解引用**（dereference）指针，访问其指向的数据：

```rust
let x = Box::new(5);
let y = *x;        // 解引用，y 的值为 5
```

```cpp
// C++ 类比
int* x = new int(5);
int y = *x;        // 解引用，相同语法
delete x;
```

> 补充：Rust 的 `Box` 类似 C++ 的 `std::unique_ptr`——拥有堆数据的所有权，离开作用域自动释放。区别在于 Rust 不需要手动 `delete`，且不允许复制 `Box`（只能移动）

Rust 在很多场景下会自动插入解引用（如方法调用），因此你很少需要手动写 `*`：

```rust
let s = String::from("hello");
let len = s.len();       // 隐式解引用 + 自动借用
let len = str::len(&s);  // 与上一行等价，显式写法
```

### 2.3 别名与可变性

引用带来了**别名**（aliasing）——多个变量指向同一块数据。别名本身无害，但如果同时允许修改，就会产生问题：

```rust
let mut v = vec![1, 2, 3];
let num = &v[2];    // num 是 v[2] 的引用（别名）
v.push(4);          // v 被修改，可能触发重新分配
// println!("{num}"); // num 可能指向已释放的内存！
```

`push` 可能导致 `Vec` 重新分配内存，原来的元素被释放，`num` 就成了悬垂引用。这就是未定义行为

```cpp
// C++ 中同样的问题
std::vector<int> v = {1, 2, 3};
int& num = v[2];       // num 是 v[2] 的引用
v.push_back(4);        // 可能触发重新分配，num 变为悬垂引用
std::cout << num;      // 未定义行为！
```

### 2.4 借用检查器与权限系统

Rust 通过**借用检查器**（borrow checker）解决别名与修改的冲突。核心思想是：**数据不能同时被别名和修改**

借用检查器使用三种**权限**来跟踪变量的使用状态：

| 权限 | 全称  | 含义                 |
| ---- | ----- | -------------------- |
| R    | Read  | 数据可以被读取       |
| W    | Write | 数据可以被修改       |
| O    | Own   | 数据可以被移动或释放 |

默认情况下，变量拥有 **R + O** 权限。如果声明为 `let mut`，则额外获得 **W** 权限

创建引用时，权限会从原变量**转移**到引用上：

| 场景              | 原变量权限   | 引用权限     |
| ----------------- | ------------ | ------------ |
| 不可变引用 `&v`   | 失去 W、O    | 获得 R、O    |
| 可变引用 `&mut v` | 失去 R、W、O | 获得 R、W、O |

引用的生命周期结束后，权限归还给原变量

### 2.5 权限变化示例

以下代码展示了不可变引用期间权限的变化：

```rust
let mut v = vec![1, 2, 3];   // L1
let num = &v[2];             // L2
println!("{num}");           // L3
```

| 行 | 操作                    | `v` 的权限        | `num` 的权限      |
| --- | ----------------------- | ----------------- | ----------------- |
| L1 | `let mut v = vec![...]` | R + W + O         | —                 |
| L2 | `let num = &v[2]`       | R + O（失去 W）   | R + O             |
| L3 | `println!("{num}")`     | R + W + O（归还） | —（生命周期结束） |

借用 `&v[2]` 使 `v` 临时失去 W 权限——所以此时不能修改 `v`。`num` 使用完毕后，权限归还，`v` 恢复为 R + W + O

再看可变引用的情况：

```rust
let mut v = vec![1, 2, 3];   // L1
let num = &mut v[2];         // L2
*num += 1;                   // L3
v.push(4);                   // L4
```

| 行 | 操作                    | `v` 的权限        | `num` 的权限      |
| --- | ----------------------- | ----------------- | ----------------- |
| L1 | `let mut v = vec![...]` | R + W + O         | —                 |
| L2 | `let num = &mut v[2]`   | —（全部失去）     | R + W + O         |
| L3 | `*num += 1`             | —                 | R + W + O         |
| L4 | `v.push(4)`             | R + W + O（归还） | —（生命周期结束） |

可变引用期间 `v` **完全不可用**——不能读取、不能修改、不能释放。这就是"不能同时别名和修改"的实现方式

### 2.6 不可变引用

```rust
fn first(strings: &Vec<String>) -> &String {
    &strings[0]
}
```

不可变引用（`&T`）允许**读取**但禁止**修改**。多个不可变引用可以同时存在

### 2.7 可变引用

```rust
fn add_suffix(name: &mut String) {
    name.push_str(" Jr.");
}
```

可变引用（`&mut T`）允许**修改**数据，但同一时间只能有一个可变引用，且不能与不可变引用共存。这就是借用检查器的核心规则：**不能同时存在别名和修改**

```rust
let mut v = vec![1, 2, 3];
let num = &v[2];      // 不可借
v.push(4);            // 可变借用，冲突
```

编译器会拒绝这段代码：

```text
error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable
```

### 2.8 生命周期参数

当函数的参数和返回值都包含引用时，Rust 需要知道返回的引用来自哪个参数——这就是**生命周期**（lifetime）的问题。例如：

```rust
fn first_or<'a>(strings: &'a Vec<String>, default: &'a String) -> &'a String {
    if strings.is_empty() {
        default
    } else {
        &strings[0]
    }
}
```

`'a` 标注表示返回值的引用与两个参数的引用活得一样久。生命周期将在后续章节详细讲解

## Part 3 修复所有权常见错误

### 3.1 不可变引用与可变修改

```rust
let mut v = vec![1, 2, 3];
let num = &v[2];
v.push(4);
println!("{num}");
```

三种修复方式：

**方式一：不在引用期间修改**

```rust
let mut v = vec![1, 2, 3];
v.push(4);              // 先修改
let num = &v[2];        // 后借用
println!("{num}");      // 引用在使用后立即结束
```

**方式二：使用作用域限制引用生命周期**

```rust
let mut v = vec![1, 2, 3];
{
    let num = &v[2];
    println!("{num}");  // 引用在此结束
}
v.push(4);              // 借用已结束，可以修改
```

**方式三：克隆数据，避免引用**

```rust
let mut v = vec![1, 2, 3];
let num = v[2].clone(); // 深拷贝，不持有 v 的引用
v.push(4);
println!("{num}");
```

### 3.2 返回引用

不要返回局部变量的引用——局部变量在函数返回时被释放，引用会成为悬垂引用：

```rust
fn dangling() -> &String {
    let s = String::from("hello");
    &s    // 错误：s 在函数返回后被释放
}
```

修复方式：

- **返回所有权**（移动）而非引用
- 使用 `static` 全局生命周期
- 使用 `Rc` / `Arc` 共享所有权

### 3.3 Copy 与 Move 的区别

实现 `Copy` trait 的类型在赋值时**复制**，原变量仍然有效：

```rust
let a: i32 = 5;
let b = a;       // 复制，a 仍然有效
println!("{a}"); // 合法
```

未实现 `Copy` 的类型（如 `String`、`Vec`）在赋值时**移动**，原变量失效：

```rust
let s1 = String::from("hello");
let s2 = s1;     // 移动，s1 失效
// println!("{s1}"); // 编译错误
```

```cpp
// C++ 中的情况
std::string s1 = "hello";
std::string s2 = s1;    // 复制，s1 仍然有效
std::cout << s1;        // 合法
```

> 补充：C++ 默认进行浅拷贝，两个变量指向同一块堆内存，需要析构函数来避免重复释放。Rust 的策略更明确：赋值要么复制（`Copy` 类型），要么移动（转移所有权），不存在"两个变量共享堆内存但没有明确的释放规则"的情况

简单判断：如果类型仅包含栈上数据且实现了 `Copy`，赋值就是复制；如果包含堆数据（如 `String`、`Vec`、`Box`），赋值就是移动

## 小结

| 概念              | 一句话                                         |
| ----------------- | ---------------------------------------------- |
| 所有权            | 每个值有且只有一个所有者，离开作用域自动释放   |
| 移动（Move）      | 堆数据赋值时转移所有权，原变量失效             |
| 复制（Copy）      | 栈数据赋值时复制值，原变量仍然有效             |
| 引用（Reference） | `&T` 或 `&mut T`，借用数据但不获取所有权       |
| 不可变引用        | 允许多个同时存在，禁止修改数据                 |
| 可变引用          | 同时只能有一个，允许修改，不能与不可变引用共存 |
| 借用检查器        | 通过 R/W/O 权限确保数据不同时被别名和修改      |
| 生命周期          | 数据必须比其所有引用活得更久                   |

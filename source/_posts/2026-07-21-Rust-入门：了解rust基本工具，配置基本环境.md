## Rust的基本工具

Rust 的语言工具链由三个核心组件构成：**rustup**（版本管理器）、**cargo**（包管理与构建工具）和 **rustc**（编译器）

在实际开发中其实几乎不会直接调用 **rustc** ，更多使用的是 **rustup** 和 **cargo**

## rustup：安装与管理 Rust 版本

rustup 是 Rust 官方的工具链安装器，一条命令即可完成安装：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
# 确认安装成功
rustc --version
cargo --version
```

安装后，rustup 管理着本地所有的 Rust 版本

常用命令：

| 命令 | 作用 |
| --- | --- |
| `rustup update` | 更新到最新 stable 版本 |
| `rustup show` | 查看当前激活的工具链信息 |
| `rustup default nightly` | 切换到 nightly 版本 |
| `rustup component add clippy` | 安装额外组件（如 linter） |
| `rustup toolchain list` | 列出已安装的所有版本 |

## Cargo

cargo 承担了 Rust 项目从创建到发布的全部流程。以下展示一些常用的场景

### 创建项目

```bash
cargo new hello_world          # 创建二进制项目
cargo new my_lib --lib         # 创建库项目
cargo init                     # 在当前目录初始化项目
```

每个项目根目录下会生成一个 `Cargo.toml`，具体是什么后面会讲到

### 编译与运行

```bash
cargo build                    # 编译（debug 模式），产物在 target/debug/
cargo build --release          # 编译（release 模式，含优化），产物在 target/release/
cargo run                      # 编译并运行
cargo check                    # 仅检查语法，不生成二进制（速度更快）
```

日常开发中，`cargo run` 是最常用的命令。当我们只是想检查编译是否存在问题时，`cargo check` 比 `cargo build` 更快，更合适

### 测试与代码质量

```bash
cargo test                     # 运行所有测试
cargo test test_name           # 运行名称匹配的测试
cargo fmt                      # 格式化代码
cargo clippy                   # 运行 linter（需先 rustup component add clippy）
```

### 依赖管理

```bash
cargo add rand                     # 添加依赖（自动写入 Cargo.toml）
cargo add serde --features derive  # 添加依赖并启用 features
cargo update                       # 更新依赖（受 Cargo.toml 版本约束限制）
cargo tree                         # 查看依赖树
```

### 发布

```bash
cargo doc --open               # 生成并打开文档
cargo publish                  # 发布到 crates.io
```

### Workspace

当一个项目包含多个子 crate 时，可以用 workspace 统一管理。根目录的 `Cargo.toml` 中声明 `[workspace]` 成员，所有子 crate 共享同一个 `Cargo.lock` 和 `target/` 目录，避免重复编译：

```toml
[workspace]
members = ["crate_a", "crate_b"]
resolver = "3"
```

## Cargo.toml：项目的身份证

`Cargo.toml` 是每个 Rust 项目的配置文件，使用 [TOML](https://toml.io) 格式。一个典型的例子：

```toml
[package]
name = "guessing_game"
version = "0.1.0"
edition = "2024"

[dependencies]
rand = "0.3.14"
```

`[package]` 记录项目元信息：名称、版本号和 Rust edition（语言版本，会随 Rust 每三年一个大版本迭代，如 2015、2018、2021、2024）。

`[dependencies]` 声明项目的依赖。版本号 `"0.3.14"` 是 [SemVer](https://semver.org) 语义化版本，cargo 会将其解释为 `^0.3.14`，即允许 `>=0.3.14` 且 `<0.4.0` 的版本

也可以精确指定，具体使用方式如下：

```toml
rand = "=0.3.14"                # 仅 0.3.14
rand = ">=0.3, <0.4"            # 范围约束
rand = { git = "https://..." }  # 从 git 仓库拉取
```

除此之外，`Cargo.toml` 还可包含 `[dev-dependencies]`（仅测试/example 需要的依赖）、`[build-dependencies]`（构建脚本用）、`[profile]`（编译优化级别）等配置段落。

## Cargo.lock：版本的快照

`Cargo.toml` 只声明了版本的「约束范围」，而 `Cargo.lock` 记录了实际解析锁定后的每一个具体版本——包括依赖的依赖。这让同一个项目的所有开发者和 CI 环境都能得到完全一致的依赖版本

`Cargo.toml` 明确版本范围 ，`Cargo.lock` 记录上次构建时使用的是哪个版本

对于二进制项目（如 `cargo new` 创建的默认项目），建议将 `Cargo.lock` **纳入版本控制**（git commit），确保可复现构建。对于库项目，可以进行选择性提交，因为下游用户会根据他们自己的依赖解析来决定最终版本

当执行 `cargo update` 时，cargo 会在 `Cargo.toml` 范围内重新解析依赖并更新 `Cargo.lock` 中的记录

## 小结

| 工具 | 职责 |
| --- | --- |
| rustup | 安装和切换 Rust 工具链版本 |
| cargo | 构建、测试、依赖管理、发布 |
| Cargo.toml | 声明项目信息和依赖约束 |
| Cargo.lock | 锁定依赖的精确版本 |

`ownership` 示例覆盖了所有权的核心概念，下面按代码出现的顺序逐一说明

## 移动与函数传参

```rust
fn greet(g1: String, g2: String) {
    println!("{} {}", g1, g2);
}

fn main() {
    let m1 = String::from("hello");
    let m2 = String::from("world");
    greet(m1, m2);
    let s = format!("{} {}", m1, m2);
}
```

`greet(m1, m2)` 将两个 `String` 的所有权移动到了函数参数 `g1`、`g2` 中。函数返回后 `g1`、`g2` 被释放，`m1`、`m2` 不再有效，后续使用会编译报错

**修复：函数返回所有权**

```rust
fn greet(g1: String, g2: String) -> (String, String) {
    println!("{} {}", g1, g2);
    (g1, g2)
}

fn main() {
    let m1 = String::from("hello");
    let m2 = String::from("world");
    let (m1_again, m2_again) = greet(m1, m2);
    let s = format!("{} {}", m1_again, m2_again);
}
```

将所有权通过返回值传回调用者。这种方式可以工作，但每次都要把所有权传来传去，非常繁琐

**更好的修复：使用引用传参**

```rust
fn greet(g1: &String, g2: &String) {
    println!("{} {}", g1, g2);
}

fn main() {
    let m1 = String::from("hello");
    let m2 = String::from("world");
    greet(&m1, &m2);
    let s = format!("{} {}", m1, m2);
}
```

`&m1` 借用 `m1`，不转移所有权。函数返回后 `m1`、`m2` 仍然有效

## 解引用

```rust
let m1 = String::from("hello");
println!("{}", m1);
println!("{}", &m1);
```

两行输出相同。`println!` 宏会自动处理引用和解引用，`m1` 和 `&m1` 在此场景下等价

Rust 在方法调用时会自动插入解引用，因此你很少需要手动写 `*`

## RWO 权限系统

借用检查器使用三种权限来跟踪变量状态：

| 权限 | 含义 |
| --- | --- |
| R（Read） | 数据可以被读取 |
| W（Write） | 数据可以被修改 |
| O（Own） | 数据可以被移动或释放 |

### 不可变引用期间的权限变化

```rust
let mut v = vec![1, 2, 3, 4, 5];
let num = &v[0];           // L1
println!("{}", *num);       // L2
v.push(6);                 // L3
```

| 行 | `v` 的权限 | `num` 的权限 |
| --- | --- | --- |
| L1 | R + O（失去 W） | R + O |
| L2 | R + O | R + O |
| L3 | R + W + O（归还） | —（生命周期结束） |

借用 `&v[0]` 使 `v` 临时失去 W 权限，所以中间不能修改 `v`。`num` 使用完毕后，权限归还

### 不可变引用导致修改失败

```rust
let mut v = vec![1, 2, 3, 4, 5];
let num = &v[0];
v.push(6);                 // 错误：v 被不可变借用，无法修改
println!("{}", *num);
```

编译器报错：

```text
error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable
```

`num` 还在使用中（`println!` 在后面），`v` 的 W 权限尚未归还，因此 `push` 被拒绝

### 可变引用期间的权限变化

```rust
let mut v = vec![1, 2, 3, 4, 5];
let num = &mut v[2];       // L1
*num += 1;                 // L2
println!("{}", *num);       // L3
println!("{:?}", v);        // L4
```

| 行 | `v` 的权限 | `num` 的权限 |
| --- | --- | --- |
| L1 | —（全部失去） | R + W + O |
| L2 | — | R + W + O |
| L3 | — | R + W + O |
| L4 | R + W + O（归还） | —（生命周期结束） |

可变引用期间 `v` **完全不可用**——不能读取、不能修改、不能释放

### 可变引用降级为不可变引用

```rust
let mut v = vec![1, 2, 3, 4, 5];
let num = &mut v[2];
let num2 = &*num;  // 降级为不可变引用
```

`&*num` 先解引用再取不可变引用，`num2` 是只读的，`num` 的 W 权限被临时移除

### 权限在引用生命周期结束时归还

```rust
let mut x = 1;
let y = &x;       // L1
let z = *y;       // L2
x += z;           // L3
```

| 行 | `x` 的权限 | `y` 的权限 |
| --- | --- | --- |
| L1 | R + O | R + O |
| L2 | R + O | R + O |
| L3 | R + W + O（归还） | — |

`*y` 是 `y` 的最后一次使用，之后 `y` 的生命周期结束，`x` 恢复 W 权限

### 条件分支中的权限归还

```rust
fn ascii_capitalize(v: &mut Vec<char>) {
    let c = &v[0];
    if c.is_ascii_lowercase() {
        let up = c.to_ascii_uppercase();
        v[0] = up;
    } else {
        println!("{:?}", v);
    }
}
```

`c` 的生命周期在 `to_ascii_uppercase()` 之后结束。在 `if` 分支中，`v[0] = up` 在 `c` 不再使用后执行，因此 `v` 已恢复 W 权限，可以编译通过

## 数据必须比其所有引用活得更久

```rust
let s = String::from("hello world");
let s_ref = &s;
drop(s);
println!("{}", s_ref);
```

`&s` 使 `s` 失去 O 权限，但 `drop(s)` 需要 O 权限才能释放数据，产生冲突。编译器拒绝这段代码

## 返回引用的常见错误

### 悬垂引用

```rust
fn return_a_string() -> &String {
    let s = String::from("hello world");
    let s_ref = &s;
    s_ref    // 错误：s 在函数返回后被释放
}
```

### 修复方式

**返回所有权（移动）：**

```rust
fn return_a_string() -> String {
    let s = String::from("hello world");
    s
}
```

**使用 `static` 字符串字面量：**

```rust
fn return_a_string() -> &'static str {
    "hello world"
}
```

**使用 `Rc` 共享所有权：**

```rust
use std::rc::Rc;

fn return_a_string() -> Rc<String> {
    let s = Rc::new(String::from("hello world"));
    Rc::clone(&s)
}
```

**通过可变引用写入调用者提供的变量：**

```rust
fn return_a_string(output: &mut String) {
    output.replace_range(.., "hello world");
}
```

## 流动权限

当函数的参数和返回值都包含引用时，编译器需要确认返回的引用来自哪个参数：

```rust
fn first(strings: &Vec<String>) -> &String {
    let s_ref = &strings[0];
    s_ref
}
```

返回值 `s_ref` 显然来自 `strings`，编译器可以推断

但如果存在多个可能的来源：

```rust
fn first_or(strings: &Vec<String>, default: &String) -> &String {
    if strings.len() > 0 {
        &strings[0]
    } else {
        default
    }
}
```

编译器无法确定返回值来自 `strings` 还是 `default`，需要显式标注生命周期：

```rust
fn first_or<'a>(strings: &'a Vec<String>, default: &'a String) -> &'a String {
    if strings.len() > 0 {
        &strings[0]
    } else {
        default
    }
}
```

生命周期将在后续章节详细讲解

### 返回局部变量的引用

```rust
fn return_a_string() -> &String {
    let s = String::from("hello world");
    let s_ref = &s;
    s_ref    // 错误：s 在函数返回后被释放
}
```

```rust
fn main() {
    let value = return_a_string();
    println!("{}", value);
}
```

`return_a_string` 中的 `s` 是局部变量，返回后被释放，`s_ref` 成为悬垂引用

## Copy 与 Move 的区别

对于仅包含栈数据的类型，解引用后复制值，原变量仍然有效：

```rust
let v = vec![1, 2, 3, 4, 5];
let n_ref = &v[0];
let n = *n_ref;        // 解引用 i32，复制值，合法
```

对于包含堆数据的类型，解引用试图复制 `String`——但 `String` 没有实现 `Copy`：

```rust
let v = vec![String::from("hello"), String::from("world")];
let s_ref = &v[0];
let s = *s_ref;        // 错误：String 不支持 Copy
```

简单判断：如果类型仅包含栈上数据且实现了 `Copy`，赋值就是复制；如果包含堆数据（如 `String`、`Vec`、`Box`），赋值就是移动

## 小结

| 概念 | 一句话 |
| --- | --- |
| 移动传参 | 堆数据传参时转移所有权，原变量失效 |
| 返回所有权 | 函数可通过返回值将所有权传回调用者 |
| 引用传参 | `&T` 借用数据，不转移所有权，函数返回后原变量仍然有效 |
| R/W/O 权限 | 借用检查器通过权限跟踪确保数据安全 |
| 不可变借用 | 失去 W 权限，期间不能修改 |
| 可变借用 | 失去全部权限，期间完全不可用 |
| 权限归还 | 引用生命周期结束后，权限归还给原变量 |
| 悬垂引用 | 返回局部变量的引用会导致未定义行为 |
| Copy vs Move | 栈数据复制，堆数据移动 |

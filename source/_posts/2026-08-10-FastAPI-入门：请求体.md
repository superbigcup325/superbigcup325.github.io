之前提到的路径参数，查询参数都解决简单的信息传输任务。但真实接口在创建、修改资源时，往往要传一整块结构化数据：新建一篇文章，得带上标题、正文、分类、标签……这么一组字段塞不进 URL，得放进 HTTP 请求的**请求体（request body）**里。本篇就来认识请求体：它和响应体是什么关系，FastAPI 怎么用 Pydantic 声明它、解析它、校验它，以及它怎么和路径参数、查询参数搭着用

## Part 1 请求体是什么：请求体 vs 响应体

请求体（request body）是客户端发给 API 的数据，响应体（response body）是 API 发回给客户端的数据——这是一对相对的概念。API 几乎总是要发响应体（接口总得回点什么），但客户端不一定每次都带请求体：有时候只是访问一个路径、带几个查询参数，不送任何 body

那么请求体一般什么时候出现？凡是要"往服务器传数据"的操作就该用它。规范上，发送数据应使用 `POST`（最常见）、`PUT`、`DELETE`、`PATCH` 这几个方法；`GET` 一般不带请求体——规范里 `GET` 带 body 是未定义行为，FastAPI 虽然为极端场景支持了它，但交互式文档（Swagger UI）不会给 `GET` 接口展示 body 的说明，中间的代理服务器也未必支持，所以别把结构化数据塞进 `GET`

| 概念                   | 含义                                    |
| -------------------- | ------------------------------------- |
| 请求体 request body     | 客户端发给 API 的数据，常用于 `POST`/`PUT` 传结构化数据 |
| 响应体 response body    | API 发回给客户端的数据，几乎每个接口都有              |

声明请求体要用到 Pydantic，需要手动导入

## Part 2 用 Pydantic 处理请求体

FastAPI 声明请求体的方式是 Pydantic 模型——继承 `BaseModel` 的类，能拿到 Pydantic 的全部能力。完整的第一个例子：

```python
from fastapi import FastAPI
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

app = FastAPI()

@app.post("/items/")
async def create_item(item: Item):
    return item
```

拆成三步看：

### 继承 BaseModel，声明数据类型

定义一个类，继承 `BaseModel`，字段用标准 Python 类型标注，这个模型就描述了请求体的结构。`Item` 模型声明了四个字段：

| 字段          | 类型          | 默认值   | 是否必填 |
| ----------- | ----------- | ----- | ---- |
| `name`      | `str`       | 无     | 必填   |
| `description` | `str \| None` | `None` | 选填   |
| `price`     | `float`     | 无     | 必填   |
| `tax`       | `float \| None` | `None` | 选填   |

和查询参数同一套规矩：**字段带默认值就不必填，不写默认值就必填，用 `None` 作默认值表示完全可选**。于是 `description`、`tax` 可有可无

示例合法 JSON：

```json
{
  "name": "Foo",
  "description": "An optional description",
  "price": 45.2,
  "tax": 3.5
}
```

省略选填字段、只传 `name` 和 `price`，同样合法：

```json
{
  "name": "Foo",
  "price": 45.2
}
```

### 声明为参数

像声明路径参数、查询参数那样，把模型类当参数类型写在函数签名里：`item: Item`。这里的 `item` 是一个 Pydantic 模型对象，声明之后就能在函数里正常使用——访问 `item.name`、`item.price`，编辑器也会对模型字段给出自动补全和类型提示

### 最终结果：自动解析、校验、文档

仅凭这一行类型声明，FastAPI 就能在收到请求后自动完成这一整套：

| FastAPI 自动做的事    | 说明                                        |
| ----------------- | ----------------------------------------- |
| 读 JSON           | 把请求体当 JSON 读取                            |
| 类型转换            | 按字段声明转成对应类型，如 JSON 里的 `45.2` → Python 的 `float` |
| 数据校验            | 缺必填字段、类型不对，返回清晰的标准错误，指明错在哪、错什么；校验不过就是 422 |
| 注入数据            | 把解析好的模型对象放进参数 `item` 传给你                |
| 生成 JSON Schema  | 为模型生成 JSON Schema 并入 OpenAPI，自动文档直接用       |

文档侧：模型的 JSON Schema 会出现在 `/docs`、`/redoc` 对应接口里，展示 request body 的字段结构、标注哪些必填，前端对接照着填就行

编辑器侧也有一份红利：因为 `item` 被声明成 `Item` 模型，函数内部写 `item.` 就有字段补全，类型不匹配的运算还会被编辑器标红——这个体验不是巧合，整个框架就是围绕"类型声明驱动"这一设计建的，路径参数篇、查询参数篇享受过的编辑器支持，请求体这里一点不少

模型对象在函数里怎么用？除了直接 `return item`（FastAPI 会把它序列化成 JSON 响应），也可以访问属性做加工。官方教程的进阶示例（`tutorial002`）示范了"用模型"的姿势：

```python
@app.post("/items/")
async def create_item(item: Item):
    item_dict = item.model_dump()
    if item.tax is not None:
        price_with_tax = item.price + item.tax
        item_dict.update({"price_with_tax": price_with_tax})
    return item_dict
```

`item.model_dump()` 把模型转成 Python 字典，之后就能像普通 dict 一样增删字段，最后把加工结果返回给客户端

## Part 3 多种搭配：请求体 + 路径参数 + 查询参数

请求体不一定要单独出现，可以跟路径参数、查询参数同时声明在一个函数里

先看"请求体 + 路径参数"更新某个 `item`，资源定位走路径参数 `item_id`，新数据走请求体：

```python
@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, **item.model_dump()}
```

向 `/items/3` 发 `PUT`，body 放 `{"name": "Foo", "price": 45.2}`：`item_id` 从路径来，`item` 从请求体来，各取各的、互不干扰。再把查询参数也加进来（官方教程 `tutorial004`）：

```python
@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item, q: str | None = None):
    result = {"item_id": item_id, **item.model_dump()}
    if q:
        result.update({"q": q})
    return result
```

三种来源凑齐，FastAPI 的识别规则是：

| 参数        | 类型                  | 从哪取数                       | 必选规则                  |
| --------- | ------------------- | -------------------------- | --------------------- |
| `item_id` | `int`               | 路径参数，`/items/{item_id}` 占位符 | 必选：路径匹配不上就没有这个接口     |
| `item`    | `Item`（Pydantic 模型） | 请求体                        | 必选：缺字段或类型不符返回 422   |
| `q`       | `str \| None`       | 查询参数，`?q=...`              | 可选：默认 `None`           |

规则一句话：**和路径占位符同名的参数 → 路径参数；Pydantic 模型类型的参数 → 请求体；其余单个类型（`int`、`str`、`bool`……）→ 查询参数**。请求体是"对象"，路径/查询参数是"单值"，FastAPI 看声明就能分辨

跑起来之后，向 `/items/1?q=hi` 发 `PUT`、body 为 `{"name": "Foo", "price": 45.2}`，返回：

```json
{"item_id": 1, "name": "Foo", "price": 45.2, "q": "hi"}
```

`q` 声明成 `str | None` 且默认值是 `None`，所以可选。注意一个细节：**决定参数"可选还是必选"的是有没有默认值 `= None`，而不是联合类型 `str | None` 本身**——加上类型注解是为了让编辑器提供更好的支持、更早发现类型错误

## 小结

| 概念        | 一句话                                                     |
| --------- | ------------------------------------------------------- |
| 请求体       | 客户端发给 API 的结构化数据（JSON），与响应体相对；常用 `POST`/`PUT`，`GET` 规范上不带 |
| Pydantic 模型 | 继承 `BaseModel` 的类，字段用标准类型标注；不写默认值必填、带默认值可选、`None` 显式可选     |
| 声明方式      | 把模型类作为函数参数类型（`item: Item`），和路径/查询参数同一套写法               |
| 自动处理      | 读 JSON、类型转换、数据校验（422）、注入参数、生成 JSON Schema 进文档         |
| 用模型       | 直接返回模型，或 `model_dump()` 转 dict 加工后再返回                  |
| 多种搭配      | 路径参数定位资源、查询参数过滤单值、模型参数接请求体，FastAPI 按声明各归各位            |

`modules` 示例覆盖了 Rust 模块系统的主要用法，下面按概念逐一说明

## Part 1 Crate：编译单元

**crate** 是编译器一次处理的最小代码单位，分为两种形式：

| 类型          | 入口          | 产物        | 用途               |
| ------------- | ------------- | ----------- | ------------------ |
| binary crate  | `main()` 函数 | 可执行文件  | 命令行程序、服务   |
| library crate | 无 `main()`   | 库（.rlib） | 被其他项目共享复用 |

**crate root** 是编译器的起始源文件，构成 crate 模块树的根：

- binary crate：`src/main.rs`
- library crate：`src/lib.rs`

crate 内部其实是一棵**模块树**，而不仅仅是单个文件

## Part 2 Package：Cargo 的打包单位

**package** 是携带 `Cargo.toml` 的一个或多个 crate 的捆绑。package 与 crate 的区别就是：package 一定有 `Cargo.toml`，描述如何构建这些 crate

package 的规则：

- 至少包含一个 crate（binary 或 library 均可）
- binary crate 可以有多个（放入 `src/bin/`，每个文件是一个独立 crate）
- library crate 最多一个

创建命令：

```console
$ cargo new my-project          # 创建 binary crate 的 package
$ cargo new my-project --lib    # 创建 library crate 的 package
```

生成的目录结构：

```
my-project
├── Cargo.toml       # package 的配置文件
└── src
    ├── main.rs      # binary crate root
    └── lib.rs       # library crate root（可选，两者可共存）
```

> 约定：`src/main.rs` 对应与 package 同名的 binary crate，`src/lib.rs` 对应同名 library crate。一个 package 同时包含两者时，binary 通常只负责启动，逻辑都在 library 中

## Part 3 Module：组织代码与隐私控制

**module** 允许把 crate 内的代码分组，并控制各项的可见性。模块可以嵌套，形成**模块树**，根是 `crate`：

```
crate
 └── front_of_house
     ├── hosting
     │   └── add_to_waitlist
     └── serving
         └── take_order
```

> 模块树类似文件系统的目录树，模块就是目录，代码就是文件

### 3.1 声明方式

模块有三种声明与存放方式：

**方式一：内联（inline）**，模块直接定义在文件中：

```rust
mod garden {
    pub mod vegetables {
        pub struct Asparagus {}
    }
}
```

**方式二：单文件**，`mod garden;` 会在同目录查找 `garden.rs`：

```rust
mod garden;   // 查找 src/garden.rs
```

```
src
├── main.rs
└── garden.rs
```

**方式三：目录**，`mod garden;` 查找 `garden/mod.rs`（旧风格）或 `garden.rs`（新风格），适合子模块较多的模块：

```rust
mod garden;   // 查找 src/garden/mod.rs
```

```
src
├── main.rs
└── garden
    ├── mod.rs
    └── vegetables.rs
```

> 模块的代码默认是私有的。`mod` 不是 include——只需在模块树中声明一次，其他文件通过路径引用

## Part 4 Path：路径

要调用模块树中的项，需要给出它的路径。路径有两种形式，用 `::` 连接：

### 4.1 绝对路径

从 crate 根开始，以 `crate` 开头（类似文件系统的 `/`）：

```rust
crate::front_of_house::hosting::add_to_waitlist();
```

### 4.2 相对路径

从当前模块开始，以模块名、`self` 或 `super` 开头（类似 `./` 与 `../`）：

```rust
// 当前模块下
front_of_house::hosting::add_to_waitlist();

// super 指向父模块
super::deliver_order();
```

| 写法          | 起点     | 类似文件系统 |
| ------------- | -------- | ------------ |
| `crate::a::b` | crate 根 | `/a/b`       |
| `self::a::b`  | 当前模块 | `./a/b`      |
| `super::a::b` | 父模块   | `../a/b`     |

> 一般推荐绝对路径：代码定义与调用点独立移动时，绝对路径更容易保持正确

## Part 5 可见性：pub 关键字

Rust 默认所有项（模块、函数、struct、字段）**对外私有**，用 `pub` 逐级公开：

```rust
mod front_of_house {
    pub mod hosting {        // 模块公开
        pub fn add_to_waitlist() {}   // 函数也要公开
    }
}
```

> `pub mod` 只让外部能"到达"该模块，模块内容的可访问性仍需逐项声明 `pub`

### 5.1 struct 字段的 pub

struct 公开后，字段默认仍然私有，可以逐字段设置 `pub`：

```rust
mod back_of_house {
    pub struct Breakfast {
        pub toast: String,        // 公开字段，外部可读写
        seasonal_fruit: String,   // 私有字段，外部不可访问
    }

    impl Breakfast {
        // 存在私有字段时，必须提供公开构造函数
        pub fn summer(toast: &str) -> Breakfast {
            Breakfast {
                toast: String::from(toast),
                seasonal_fruit: String::from("peaches"),
            }
        }
    }
}
```

### 5.2 enum 的 pub

enum 设为 `pub` 后，所有变体自动公开（枚举变体没有意义不公开）：

```rust
pub enum Appetizer {
    Soup,
    Salad,
}
```

## Part 6 Use：引用路径

完整路径写起来冗长，用 `use` 把路径引入当前作用域，之后就可以用短名：

```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}

use crate::front_of_house::hosting;   // 引入模块

pub fn eat_at_restaurant() {
    hosting::add_to_waitlist();       // 短名调用
}
```

> `use` 类似文件系统的"符号链接"，只对当前作用域生效

### 6.1 惯用法

- 函数：引入其**父模块**，调用时写 `module::fn()`
- struct / enum：引入**完整路径**

```rust
use std::collections::HashMap;   // 引入完整路径
use std::io;                     // 引入模块
```

### 6.2 嵌套路径 {}

多个同前缀的 use 可以合并成一行：

```rust
use std::{cmp::Ordering, io};       // 等价于 use std::cmp::Ordering; use std::io;
use std::io::{self, Write};         // self 表示前缀本身
```

### 6.3 别名 as

同名项冲突时，我们可以使用 `as` 起别名：

```rust
use std::fmt::Result;
use std::io::Result as IoResult;
```

### 6.4 重导出 pub use

`pub use` 把引入的项重新公开导出，外部代码可以用更短的路径访问：

```rust
pub use crate::front_of_house::hosting;
// 外部代码：modules::hosting::add_to_waitlist()
```

> 适合库的作者：内部结构按实现组织，对外 API 按使用者的视角组织

## Part 7 增加外部库

### 7.1 在 Cargo.toml 中声明依赖

```toml
[dependencies]
rand = "0.8.5"
```

### 7.2 使用 cargo add 命令

```console
$ cargo add rand
```

然后通过 `use` 引入：

```rust
use rand::Rng;
```

## 小结

| 概念       | 一句话                                                             |
| ---------- | ------------------------------------------------------------------ |
| crate      | 编译器的最小编译单位，binary（有 main）或 library（无 main）       |
| crate root | 编译起点：`src/main.rs` 或 `src/lib.rs`                            |
| package    | 携带 `Cargo.toml` 的 crate 捆绑，可含多个 binary、至多一个 library |
| module     | 组织代码与隐私控制的模块树，根为 `crate`                           |
| 内联模块   | `mod x {}` 直接写在文件中                                          |
| 文件模块   | `mod x;` 查找 `x.rs` 或 `x/mod.rs`                                 |
| 绝对路径   | `crate::` 开头，从根出发                                           |
| 相对路径   | 模块名、`self`、`super` 开头                                       |
| `pub`      | 逐级公开模块、函数、struct 字段                                    |
| `use`      | 引入路径到作用域，短名调用                                         |
| 嵌套路径   | `use std::{a, b}` 合并同前缀                                       |
| `as`       | 为引入项起别名                                                     |
| `pub use`  | 重导出，对外提供便捷路径                                           |

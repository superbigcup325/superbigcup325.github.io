程序设计中，数据往往不是孤立的，数据之间存在某种关系。**数据结构**（data structure）就是研究"如何组织数据，使得数据的存储和操作更高效"的学科

> 补充：可以类比仓库管理：同样一批货物，随意堆放和分类上架，取用效率完全不同

数据结构的讨论通常分为两个层面：**逻辑结构**（数据之间如何组织）和**物理存储**（数据在内存中如何存放）

## Part 1 逻辑结构

逻辑结构描述数据元素之间的抽象关系，与计算机无关。分为四类：

### 1.1 集合

元素之间**没有**任何关系，只是同属于一个整体：

```
{3, 1, 4, 5}  元素互异、无顺序、无依赖
```

常见于去重、成员判断等场景

### 1.2 线性结构

元素之间是**一对一**关系，除了首尾元素，每个元素有且仅有一个前驱和一个后继：

```
A → B → C → D → E
```

常见于排队、历史记录、待办清单等场景

### 1.3 树形结构

元素之间是**一对多**关系，每个节点可以有多个子节点：

```
        根
       /  \
      子  子
     / \
   孙  孙
```

常见于目录结构、组织架构、家族谱系等场景

### 1.4 图形结构

元素之间是**多对多**关系，任意两个元素之间都可能存在关联：

```
  A ── B
  |  /  |
  C ── D
```

常见于社交网络、地图导航、网络拓扑等场景

### 1.5 对比

| 类型 | 元素关系 | 典型例子       | 典型数据结构         |
| ---- | -------- | -------------- | -------------------- |
| 集合 | 无关系   | 去重、成员判断 | 集合（Set）          |
| 线性 | 一对一   | 排队、历史记录 | 数组、链表、栈、队列 |
| 树形 | 一对多   | 目录、组织架构 | 二叉树、堆           |
| 图形 | 多对多   | 社交网络、地图 | 图（Graph）          |

## Part 2 物理存储

逻辑结构是抽象的，落到计算机内存中时，有四种存储方式：

### 2.1 顺序存储

数据存放在**连续**的内存单元中，通过计算地址直接访问元素：

```
地址: 0x1000  0x1008  0x1010  0x1018
数据:   10      20      30      40
```
（假设每个元素占 8 字节，地址等差递增）

- 优点：支持随机访问，访问速度快，节省额外空间
- 缺点：插入和删除需要移动大量元素；大小固定，扩容困难

### 2.2 链式存储

每个数据元素除自身外，还存储**下一个元素的位置**（指针），内存单元不要求连续：

```
[10 | →] → [20 | →] → [30 | →] → [40 | ∅]
```

- 优点：插入和删除只需修改指针；大小动态可变
- 缺点：不能随机访问，必须从头遍历；每个元素需要额外的指针空间

### 2.3 索引存储

在顺序存储的基础上，额外建立一张**索引表**，通过索引快速定位数据：

```
索引表: 关键字 → 存储位置
  "张三" → 0x1000
  "李四" → 0x2000
```

> 补充：类比书籍的目录：先查目录定位页码，再翻到对应页，而不是逐页查找

- 优点：按关键字查找快，适合大量静态数据的检索
- 缺点：维护索引需要额外开销，数据更新时索引也要更新

### 2.4 散列存储（哈希存储）

根据元素的关键字，通过**哈希函数**直接计算出存储地址：

```
关键字 "apple" --哈希函数--> 地址 0x3000
```

- 优点：查找、插入、删除的平均时间复杂度都是 O(1)，极快
- 缺点：存在哈希冲突，需要处理冲突；数据无序，不适合范围查询

### 2.5 对比

| 存储方式 | 随机访问   | 插入删除         | 空间         | 典型数据结构 |
| -------- | ---------- | ---------------- | ------------ | ------------ |
| 顺序     | O(1) 快    | 慢（需移动元素） | 紧凑         | 数组         |
| 链式     | O(n) 慢    | 快（改指针）     | 额外指针开销 | 链表         |
| 索引     | 按关键字快 | 需维护索引       | 索引额外空间 | 数据库表     |
| 散列     | O(1) 极快  | O(1)             | 有空间浪费   | 哈希表       |

> 补充：逻辑结构与物理存储可以自由组合。例如栈是逻辑上的线性结构，既可以用数组（顺序）实现，也可以用链表（链式）实现

> 补充：C++ 标准库的容器也体现了不同存储方式：`std::array`/`std::vector` 是顺序存储，`std::list` 是链式存储，`std::unordered_map` 是散列存储

## Part 3 常用一览

以下是最常用的数据结构，按逻辑结构分类简述类型与使用场景：

### 3.1 线性结构

| 数据结构             | 特点                 | 使用场景                     | 查找/插入复杂度 |
| -------------------- | -------------------- | ---------------------------- | --------------- |
| 数组（Array）        | 连续内存，随机访问快 | 定长集合、矩阵运算           | O(1) / O(n)     |
| 链表（Linked List）  | 动态大小，插入删除快 | 实现队列、内存分配管理       | O(n) / O(1)     |
| 栈（Stack）          | 后进先出（LIFO）     | 函数调用、括号匹配、撤销操作 | 仅栈顶操作      |
| 队列（Queue）        | 先进先出（FIFO）     | 任务调度、消息队列、打印队列 | 仅队首/队尾操作 |
| 哈希表（Hash Table） | 键值对，O(1) 查找    | 字典、缓存、去重             | O(1) / O(1)     |

### 3.2 树形结构

| 数据结构              | 特点                   | 使用场景               | 查找/插入复杂度        |
| --------------------- | ---------------------- | ---------------------- | ---------------------- |
| 二叉树（Binary Tree） | 每个节点最多两个子节点 | 表达式解析、哈夫曼编码 | O(n) / O(n)            |
| 二叉搜索树（BST）     | 左小右大，有序         | 动态数据的有序维护     | O(log n) / O(log n)    |
| 堆（Heap）            | 最大/最小值在堆顶      | 优先队列、Top-K 问题   | O(1) 取最值 / O(log n) |
| 字典树（Trie）        | 字符串前缀共享         | 单词自动补全、拼写检查 | O(长度) / O(长度)      |

### 3.3 图形结构

| 数据结构    | 特点              | 使用场景                     |
| ----------- | ----------------- | ---------------------------- |
| 图（Graph） | 顶点 + 边，多对多 | 社交网络、最短路径、依赖分析 |

## 小结

| 概念     | 一句话                                         |
| -------- | ---------------------------------------------- |
| 数据结构 | 组织数据的方式，使存储和操作更高效             |
| 逻辑结构 | 数据之间的抽象关系：集合、线性、树形、图形     |
| 物理存储 | 数据在内存中的存放方式：顺序、链式、索引、散列 |
| 线性结构 | 一对一关系，如数组、链表、栈、队列             |
| 树形结构 | 一对多关系，如二叉树、堆                       |
| 图形结构 | 多对多关系，如图                               |
| 顺序存储 | 连续内存，随机访问快，插入删除慢               |
| 链式存储 | 指针相连，插入删除快，不能随机访问             |
| 散列存储 | 哈希函数定位，平均 O(1)，有冲突开销            |

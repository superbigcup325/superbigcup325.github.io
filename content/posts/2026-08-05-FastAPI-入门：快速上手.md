HTTP 协议的完整讲解在[《计算机网络基础：HTTP 协议》](<2026-08-05-计算机网络基础：HTTP-协议.md>)一文（独立的计算机网络知识，建议先读）；这里只捡 FastAPI 用得到的最小要点，然后看它如何落地成代码。这篇就从装环境开始：跑起第一个应用、看懂自动生成的文档，最后拆解一个接口（路径操作）的完整结构

## 前置速查：FastAPI 需要的 HTTP 要点

| 概念       | 一句话                                | FastAPI 中对应                    |
| -------- | --------------------------------- | ----------------------------- |
| HTTP 方法  | 用动词表达动作：GET 读、POST 建、PUT 改、DELETE 删 | 装饰器后缀：`@app.get()`、`@app.post()` 等 |
| URL 路径   | 指认要操作的资源                          | 装饰器里的路径，如 `@app.get("/items")`    |
| Path 参数  | 资源标识直接写在路径里，如 `/users/123`          | 路径里写 `{user_id}`，函数参数接收          |
| Query 参数 | 筛选、分页放 URL 问号后面，如 `?page=1`         | 直接声明为函数参数，自动接收                 |
| Header 参数 | 元信息（认证、标识等）放请求头                    | 函数参数声明为 `Header` 类型              |
| Body 参数  | 提交的数据放请求体（JSON）                    | 函数参数声明成 Pydantic 模型             |
| 状态码类别    | 2xx 成功、4xx 客户端错误、5xx 服务端错误          | 默认返回 200，也可用 `status_code` 指定     |

完整讲解见[《计算机网络基础：HTTP 协议》](<2026-08-05-计算机网络基础：HTTP-协议.md>)

## Part 1 环境搭建：FastAPI 与 uvicorn

写一个 FastAPI 应用需要两样东西：一个是 **FastAPI** 框架本身，一个是把应用跑起来的 **ASGI 服务器**。

先用 pip 安装 FastAPI：

```terminal
pip install fastapi
```

光装框架还不够，还需要一个服务器来监听端口、接收 HTTP 请求。官方推荐用 **uvicorn**：

```terminal
pip install "uvicorn[standard]"
```

`[standard]` 表示安装带标准依赖集的版本，会顺带装上热重载等功能需要的东西。装完后在命令行敲 `uvicorn --version`，能打印出版本号就说明环境就绪了

这两个东西分工不同，先分清楚：

| 组件     | 角色           | 一句话                                        |
| ------ | ------------ | ------------------------------------------ |
| FastAPI | Python Web 框架 | 负责业务层：路由怎么走、参数怎么取、返回什么、文档怎么生成               |
| uvicorn | ASGI 服务器     | 负责网络层：监听端口、接收 HTTP 请求、调用应用、把响应发回客户端           |

FastAPI 是**框架**，它不直接监听端口；uvicorn 是 **ASGI 服务器**，它负责把真实世界的 HTTP 请求接进来，交给 FastAPI 处理。两者配合，一个 Web 服务才完整

## Part 2 第一个示例：Hello World

新建一个文件 `main.py`，写一个最小应用：

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello World"}
```

先逐行扫一眼这段代码，把每个部分对应到[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)的 HTTP 概念上：

| 行                                   | 作用                             |
| ----------------------------------- | ------------------------------ |
| `from fastapi import FastAPI`        | 导入 `FastAPI` 这个类                 |
| `app = FastAPI()`                   | 创建应用实例，之后所有路径操作都挂在它上面           |
| `@app.get("/")`                     | 路径操作装饰器：注册「HTTP 方法 GET + 路径 /」    |
| `async def root():`                 | 路径操作函数：负责处理发往 `/` 的 GET 请求       |
| `return {"message": "Hello World"}` | 返回内容：会被自动转成 JSON 响应体              |

`FastAPI` 是一个 Python 类，`app = FastAPI()` 创建了它的一个实例（instance），之后你定义的所有接口都挂在 `app` 上；而 `@app.get("/")` 里的 `get` 就是[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)的 HTTP 方法，`"/"` 就是 URL 路径。每行的具体机制，Part 5 会拆开讲，先跑起来再说。在 `main.py` 所在目录执行：

```text
uvicorn main:app --reload
```

拆开看这个命令：

- `main:app` 是**入口**：从 `main.py` 模块里取出 `app` 这个对象
- `--reload` 开启**热重载**：修改代码保存后服务器自动重启，开发时不用手动重敲命令

启动成功后，终端会打印类似这样的行：

```text
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

这行告诉你在本地哪个地址提供服务。打开浏览器访问 http://127.0.0.1:8000，会看到：

```text
{"message": "Hello World"}
```

这是一个 JSON——正是[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)讲的 **HTTP 响应体**。你只写了 `return {"message": "Hello World"}`（一个 Python `dict`），FastAPI 自动把它转成 JSON 响应发回给客户端。协议层的打包工作，框架替你做了

套用[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)的响应结构看：浏览器收到的这行文字，其实被包在一整套 HTTP 响应里——状态行 `200 OK`、`Content-Type: application/json` 响应头，最后才是你看到的响应体

## Part 3 交互式 API 文档

服务器现在还在跑。依次在浏览器访问下面三个地址：

| 地址                               | 界面         | 说明                                  |
| -------------------------------- | ---------- | ----------------------------------- |
| http://127.0.0.1:8000/docs        | Swagger UI  | 可交互的 API 文档，页面上就能直接调用接口              |
| http://127.0.0.1:8000/redoc       | Redoc       | 另一种风格的文档界面                          |
| http://127.0.0.1:8000/openapi.json | 原始 JSON    | 用 OpenAPI 规范描述整个 API 的机器可读定义           |

先说 `/docs`。它由 **Swagger UI** 提供，页面上能看到你定义的所有接口：路径、HTTP 方法、参数、返回结构。最有用的功能是**可以直接在页面上试调**——点开接口、填好参数、点 "Try it out"，就发了一个真实请求，返回结果直接展示在页面上。相比拿 Postman 手动配置，这一步省事得多

再说 `/redoc`。它由 **ReDoc** 提供，是另一种视觉风格：把接口组织成偏"阅读"的文档样式，适合当作一份正式的接口说明来看

最后是 `/openapi.json`。它是**原始数据**——一个描述你整个 API 的 JSON 对象，机器可读。前面两个页面，本质上都是拿这份 JSON 渲染出来的

关键点：这三个界面**全部由 FastAPI 自动生成**。你没有写一行文档代码，只是定义了路径操作和函数，FastAPI 就推导出了完整的文档

（顺带一提：docs 页面上展示的路径、HTTP 方法、响应状态码，正是[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)讲过的请求结构要素——协议知识在这里直接变成了界面上的字段）

## Part 4 OpenAPI 与 schema

`/openapi.json` 里那份 JSON 遵循的规范叫 **OpenAPI**（由原来的 Swagger 规范演进而来）。它是一套**描述 API 的开放标准**：你的 API 有哪些路径、每个路径支持哪些方法、参数长什么样、返回什么数据结构，全都用统一的 JSON 结构写出来

为什么说它是 FastAPI 的核心卖点？因为**一切自动化的基础都是它**：

- 前两节的交互式文档（Swagger UI、Redoc）就是拿 OpenAPI 定义渲染出来的
- 生态里有几十种基于 OpenAPI 的工具，可以直接接进你的应用
- 可以用它**自动生成客户端代码**：前端、移动端、IoT 设备调用你的 API 时，请求封装代码一键生成，不用手写

再提一个词：**schema**。它的意思是"对某样东西的抽象描述"——不是实现它的代码，而是它"长什么样"的说明。在 FastAPI 语境下有两层含义：

| 术语         | 含义                                  |
| ---------- | ----------------------------------- |
| API schema | 描述整个 API 的 OpenAPI 定义，也就是 `/openapi.json` |
| 数据 schema  | 某份数据的字段与类型描述，比如一段 JSON 的结构              |

在 `/docs` 页面往下滚，会看到 **Schema** 区域——它展示的就是**请求和响应的数据结构**：有哪些字段、什么类型、是否必填。FastAPI 用你写的 Python 类型提示自动推导出这些定义。你负责声明类型，schema 生成由 FastAPI 包办

打开 `/openapi.json`，开头大概是这样的：

```json
{
  "openapi": "3.1.0",
  "info": {
    "title": "FastAPI",
    "version": "0.1.0"
  },
  "paths": {
    "/": {
      "get": { ... }
    }
  }
}
```

`"openapi": "3.1.0"` 声明用的规范版本，`info` 里是标题和版本，`paths` 下面则是每个路径及其支持的方法和响应定义。看到 `paths` 里出现 `"/"`、`"get"`、`"200"`，是不是很眼熟——这正是[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)讲过的**路径、HTTP 方法和状态码**，只不过从"约定"变成了机器可读的结构

## Part 5 路径操作（path operation）详解

[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)讲了 RESTful 风格的核心：**用 HTTP 方法表达动作，用 URL 表达资源**。在 FastAPI 里，实现这个约定的最小单位叫**路径操作（path operation）**。一个路径操作由三部分组成：

1. **路径操作装饰器**：`@app.get("/")` 这种写法
2. **路径操作函数**：装饰器下面那个函数
3. **返回内容**：函数里 `return` 的东西

下面逐部分拆开。

### 5.1 路径操作装饰器

先看 `@app.get("/")` 这个装饰器，它由两个概念拼起来：

- **路径（path）**：URL 里从第一个 `/` 开始的部分。在 `https://example.com/items/foo` 里，路径就是 `/items/foo`。路径也常被称为 **endpoint**（端点）或 **route**（路由）
- **操作（operation）**：指某个 HTTP 方法。`@app.get` 表示负责处理 GET 请求

换句话说——**装饰器里的 `get`、`post` 就是[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)讲的 HTTP 方法，装饰器里的路径就是 URL 路径**。[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>) RESTful 表格里那一列 HTTP 方法，到了 FastAPI 就是装饰器的后缀：

| HTTP 方法 | FastAPI 装饰器     | 通常含义   |
| ------- | -------------- | ------ |
| GET     | `@app.get()`   | 读取数据   |
| POST    | `@app.post()`  | 创建数据   |
| PUT     | `@app.put()`   | 更新数据   |
| DELETE  | `@app.delete()` | 删除数据   |

（另外还有 `@app.options()`、`@app.head()`、`@app.patch()`、`@app.trace()` 等使用较少的，需要时再查。FastAPI 不强制给某个方法规定含义，上表只是惯例，不是硬性要求）

`@something` 这种语法在 Python 里叫**装饰器（decorator）**：它"罩在"函数上面，把下面的函数接过去做些处理。FastAPI 的路径操作装饰器做的是**注册**：把"路径 + HTTP 方法"和"下面的函数"绑定起来，以后凡是发到这个路径、用这个方法的请求，就调用这个函数来处理

### 5.2 路径操作函数

装饰器下面的函数叫**路径操作函数**：

```python
@app.get("/")
async def root():
    return {"message": "Hello World"}
```

- **函数名随意**：`root` 只是内部标识，不会暴露给外部
- 这里用 `async def` 声明**异步函数**——系列第一篇《FastAPI 入门：前置知识》讲过 async/await，正好用上；写普通 `def` 也行，FastAPI 都能正确处理
- FastAPI 收到"GET 请求发往 `/`"时，会调用这个函数

### 5.3 返回内容

路径操作函数的返回值就是 HTTP 响应体。可以返回 `dict`、`list`、`str`、`int` 等，FastAPI 会**自动转成 JSON**：

```python
@app.get("/")
async def root():
    return {"message": "Hello World"}  # 自动转成 JSON 响应体发给客户端
```

（还能返回 Pydantic 模型等更复杂的对象，后续文章会看到。第一篇里说过 FastAPI 基于 Pydantic，返回的数据结构也可以由类型提示驱动）

这一步正好呼应[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)的 HTTP 知识：你在函数里 `return` 的东西，FastAPI 把它打包成完整的 HTTP 响应——补上状态行、响应头、响应体——再交给 uvicorn 发回客户端

## Part 6 项目配置：pyproject.toml 里配置入口

每次启动都要手动敲 `uvicorn main:app`，入口路径靠人记。FastAPI 官方提供了 `fastapi` 开发命令（来自 fastapi-cli），可以在 `pyproject.toml` 里配置应用入口，把启动命令固定下来：

```toml
[tool.fastapi]
entrypoint = "main:app"
```

配置后，用 `fastapi dev` 启动，它会按 `entrypoint` 从 `main` 模块导入 `app` 对象，等价于敲 `uvicorn main:app`。如果代码放在子包里（比如 `backend/main.py`），入口写成 `backend.main:app` 即可：

```toml
[tool.fastapi]
entrypoint = "backend.main:app"
```

本系列主线用 `uvicorn main:app` 直接启动——更贴近底层，ASGI 服务器的作用一目了然；`fastapi dev` 是官方推荐的开发命令（自带热重载），两种方式等价，按习惯选

## 小结

| 概念      | 一句话                                                         |
| ------- | ----------------------------------------------------------- |
| FastAPI  | Python Web 框架，负责路由、参数、文档等业务层逻辑                              |
| uvicorn  | ASGI 服务器，负责监听端口、收发 HTTP 请求；安装用 `pip install "uvicorn[standard]"` |
| 最小应用    | `from fastapi import FastAPI` → 创建 `app` 实例 → `@app.get("/")` 定义接口 → 返回 `dict` |
| 运行命令    | `uvicorn main:app --reload`，`main:app` 是入口，`--reload` 是热重载         |
| 自动生成的文档 | `/docs`（Swagger UI，可交互试调）、`/redoc`（阅读风格）、`/openapi.json`（原始定义）      |
| OpenAPI  | 描述 API 的开放标准，自动文档与自动生成客户端的基础                                 |
| schema   | 数据/API 的抽象描述；docs 页面的 Schema 区域展示请求与响应的数据结构                    |
| 路径操作装饰器 | `@app.get()` 等；`get`/`post` 就是 HTTP 方法，路径就是 URL               |
| 路径操作函数  | 处理请求的函数，`async def` 或普通 `def` 都行                                |
| 返回内容    | `return` 的 `dict` 等会被 FastAPI 自动转成 JSON 响应体                  |

[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)我们对着 HTTP 协议纸上谈兵，这一篇把最小闭环跑通了：从装环境到浏览器里看到 JSON，再到自动生成的文档

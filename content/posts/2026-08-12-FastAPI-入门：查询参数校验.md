之前提到，fastAPI 靠"类型 + 默认值"就决定参数怎么解析：`str`、`int`、`bool`，可选还是必选。但真实接口对查询参数的约束往往更多：搜索词不能太长、状态码得匹配固定格式、旧参数想标个"已弃用"……这些单靠类型注解表达不了。接下来的**查询参数与字符串校验（Query Parameters and String Validations）**：参数不止能声明类型，还能借助 `Query()` 附加校验规则和文档元数据——而新的 `Annotated` 写法让这一切既清晰又可复用。这一套声明式校验的思路，也是路径参数、请求体字段等更复杂校验的基础

## Part 1 额外校验：min_length、max_length 与正则 pattern

### 旧写法：Query() 当默认值

先从最常见的可选查询参数出发：`q` 是 `str | None`，默认值是 `None`，所以可选，`str | None` 联合类型本身不决定这个，加上它只是为了让编辑器给出更好的类型提示。现在给 `q` 加一条约束：**可传可不传，但传了长度不能超过 50 个字符**。FastAPI 旧版本（0.95.0 之前）的写法是把 `Query()` 当作参数的**默认值**，把校验规则作为参数传给 `Query`：

```python
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/")
async def read_items(q: str | None = Query(default=None, max_length=50)):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```

`Query(default=None, max_length=50)` 做了两件事：`default=None` 声明默认值是 `None`（和 `= None` 等价，参数因此可选，但显式声明了"这是个查询参数"）；`max_length=50` 附加"最长 50 个字符"的校验。加上这条之后 FastAPI 会：

- 校验数据，长度超过 50 就校验失败
- 对客户端返回清晰的错误
- 把这个参数连同约束写进 OpenAPI，自动文档 UI 里能看到

顺带一提：`Query()` 是用在**查询参数**上的，后面还会见到 `Path()`、`Body()`、`Header()`、`Cookie()`，它们接受和 `Query()` 相同的参数，分别作用于其他种类的参数

### 新写法：Annotated 包住类型

FastAPI 从 0.95.0 起加入并开始推荐 `Annotated` 写法。`Annotated` 是 Python 自带的类型注解机制，可以在一个类型上附加元数据。先把原来的类型注解 `str | None` 用 `Annotated` 包起来：

```python
q: Annotated[str | None] = None
```

这一步只是包了一层，含义和 `q: str | None = None` 完全一样：可以是 `str` 或 `None`，默认是 `None`。真正的重点是**把 `Query()` 放进 `Annotated` 里**去附加校验信息。注意默认值仍然写在函数参数那个 `= None` 位置上，`Query` 里不再重复设 `default`（规则见 Part 2）：

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/")
async def read_items(q: Annotated[str | None, Query(max_length=50)] = None):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```

`Annotated[str | None, Query(max_length=50)]` 的意思是：`q` 的类型是 `str | None`，额外带一条元数据——它是查询参数，最长 50 字符

### 更多规则

此处以最短长度和正则表达式举例

最短长度用 `min_length`，和 `max_length` 一起用，`q` 的合法长度就锁在 3 到 50 之间：

```python
@app.get("/items/")
async def read_items(
    q: Annotated[str | None, Query(min_length=3, max_length=50)] = None,
):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```

正则用 `pattern`。比如要求 `q` 必须 **精确等于** `fixedquery` 这个词：

```python
@app.get("/items/")
async def read_items(
    q: Annotated[
        str | None, Query(min_length=3, max_length=50, pattern="^fixedquery$")
    ] = None,
):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```

>> `^fixedquery$` 拆开看：`^` 表示"从这里开始，前面不能有别的字符"；`fixedquery` 要求逐字匹配这个值；`$` 表示"到这里结束，后面不能有别的字符"。三段合起来就是"只能是 `fixedquery` 这几个字符，一个不多一个不少"。正则对很多人来说都是个难点，一时看不懂没关系，FastAPI 里需要时直接照模式写就行，暂时不会正则也能做很多事

三个字符串校验规则总结：

| 校验参数     | 作用                 |
| ---------- | ------------------ |
| `min_length` | 字符串最短长度，短于它校验失败   |
| `max_length` | 字符串最长长度，超过它校验失败   |
| `pattern`   | 必须匹配的正则表达式，匹配不上校验失败 |

## Part 2 Annotated 写法与旧写法对比

把新旧两种写法摆在一起：

```python
# 新写法：Query 在 Annotated 里，默认值留在参数位置
q: Annotated[str | None, Query(max_length=50)] = None

# 旧写法：Query 当默认值，默认值搬进 Query(default=...)
q: str | None = Query(default=None, max_length=50)
```

两条规则先记住：

- **新写法里 `Query` 不能写 `default=`**。默认值只能写在函数参数那个 `= None` 位置。如果两个都写，比如 `q: Annotated[str, Query(default="rick")] = "morty"`，默认值到底是 `"rick"` 还是 `"morty"` 就说不清了，这是**不允许**的写法。要默认值就二选一：新写法 `q: Annotated[str, Query()] = "rick"`，或者旧写法 `q: str = Query(default="rick")`
- **旧写法里 `Query(default=None)` 必须手动把默认值搬进 `Query`**，等于在 `= None` 之外多抄一遍

官方推荐新代码一律用 Annotated，具体理由如下：

| Annotated优势 | 说明                                       |
| ------------ | ---------------------------------------- |
| 默认值更直观      | 函数参数的 `= None` 就是真正的默认值，符合 Python 直觉        |
| 可脱离 FastAPI 调用 | 把函数拿到别的场合调用（没有 FastAPI），行为符合预期；旧写法脱离 FastAPI 时参数拿到的是 `Query` 对象而不是真正的值，编辑器不报错，运行到函数体里才炸 |
| 可复用、可叠加     | `Annotated` 里可以放多条元数据，同一份函数签名还能配合 Typer 等工具使用 |
| 职责分离、可读性好   | 类型与校验规则集中在注解里，默认值单独留在参数位置，一眼看清           |

## Part 3 None 以外的默认值、必填参数与"必填但是 None"

### None 以外的默认值

默认值不一定是 `None`。想给 `q` 一个真实的默认值，同时要求最短 3 个字符：

```python
@app.get("/items/")
async def read_items(q: Annotated[str, Query(min_length=3)] = "fixedquery"):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```

默认值是 `"fixedquery"`，没传 `q` 就用它。**规则：默认值只要是任何类型（包括 `None`），参数就是可选的**

### 必填参数

要 `q` 必填，就**不写默认值**，在带 `Query()` 时依然成立：

```python
async def read_items(q: Annotated[str, Query(min_length=3)]):
```

### 必填但是 None

再注意一个容易混淆的变体：类型声明成 `str | None`，但**不写默认值**。类型允许 `None`，参数却是必填的：

```python
async def read_items(q: Annotated[str | None, Query(min_length=3)]):
```

这时 `q` 是**必填**的：客户端必须传这个参数，哪怕传的值是 `None`（类型允许空）。"类型可空"和"参数必填"是两码事，用表格分清：

| 写法                                 | 默认值  | 必填？ | 可空？ |
| ---------------------------------- | ---- | --- | --- |
| `Annotated[str \| None, Query(...)] = None` | `None` | 可选  | 可空  |
| `Annotated[str, Query(...)]`         | 无    | 必填  | 不可空 |
| `Annotated[str \| None, Query(...)]`   | 无    | 必填  | 可空  |

## Part 4 接受多个值：查询参数列表

查询参数还能一次性收进一个列表。声明成 `list[str]`，URL 里重复出现同名的 `q` 就会被收集成一个 Python 列表：

```python
@app.get("/items/")
async def read_items(q: Annotated[list[str] | None, Query()] = None):
    query_items = {"q": q}
    return query_items
```

请求 `http://localhost:8000/items/?q=foo&q=bar`，两个 `q` 的值 `foo`、`bar` 都会被收进 `q`，返回：

```json
{
  "q": ["foo", "bar"]
}
```

**关键点**：声明成 `list` 类型的查询参数，**必须显式用 `Query()`**，否则 FastAPI 会因为它是模型类参数，把它当成请求体（request body）处理，`list` 在这里会撞上同一条规则

### 带默认值的列表

不给任何 `q` 时给个默认列表：

```python
@app.get("/items/")
async def read_items(q: Annotated[list[str], Query()] = ["foo", "bar"]):
    query_items = {"q": q}
    return query_items
```

访问 http://localhost:8000/items/，`q` 就是默认的 `["foo", "bar"]`

### 直接写 list

类型也可以只写 `list` 不写元素类型：

```python
@app.get("/items/")
async def read_items(q: Annotated[list, Query()] = []):
    query_items = {"q": q}
    return query_items
```

注意差别：**只写 `list` 时，FastAPI 不会检查列表里装的是什么**；写 `list[int]` 才会校验（并在文档里标明）列表内容是整数。元素类型写清楚，校验和文档都更完整

## Part 5 声明元数据：title、description

`Query()` 还能给参数附加描述性信息，这些信息会写进 OpenAPI，被文档 UI 和外部工具使用。加一个 `title` 和一段 `description`，给前端对接的人看：

```python
@app.get("/items/")
async def read_items(
    q: Annotated[
        str | None,
        Query(
            title="Query string",
            description="Query string for the items to search in the database that have a good match",
            min_length=3,
        ),
    ] = None,
):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```

`title` 是参数名旁边的一句话标题，`description` 是详细说明。二者不影响校验逻辑，纯粹是给文档和工具看的"帮助性属性"。要留个心：不同工具对 OpenAPI 的支持程度不一样，个别工具可能暂时不显示这些额外信息，但多数情况下只是功能还没跟上

## Part 6 别名参数：用 alias 解决命名规范问题

URL 里写 `item-query` 这种带连字符的名字，直观也符合查询参数的习惯，但它**不是合法的 Python 变量名**。这时候我们使用 `alias`：**URL 里的名字由 `alias` 决定，Python 变量名照旧**：

```python
@app.get("/items/")
async def read_items(q: Annotated[str | None, Query(alias="item-query")] = None):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```

请求 http://127.0.0.1:8000/items/?item-query=foobaritems，FastAPI 用 `alias` 指定的 `item-query` 去 URL 里找值，传进来的还是 Python 变量 `q`

## Part 7 弃用参数与从文档排除

### deprecated：标注弃用

接口上线久了，有些参数想退休。但老客户端还在用，不能直接删，又想让文档明确提示"别用了"。直接给 `Query` 传 `deprecated=True`：

```python
@app.get("/items/")
async def read_items(
    q: Annotated[
        str | None,
        Query(
            alias="item-query",
            title="Query string",
            description="Query string for the items to search in the database that have a good match",
            min_length=3,
            max_length=50,
            pattern="^fixedquery$",
            deprecated=True,
        ),
    ] = None,
):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```

这个例子把前面的**全组合进一个 `Query()`**：`alias`、`title`、`description`、`min_length`、`max_length`、`pattern`，再加上 `deprecated=True`。校验规则、元数据、弃用标注都可以自由叠加，互不冲突。文档 UI 会把 `q` 显示为已弃用（划线标记），参数照常工作，只是明示"不建议再使用"

### include_in_schema：从 OpenAPI 排除

另一种需求是把参数**从文档里藏起来**，但接口仍然接受它。传 `include_in_schema=False`：

```python
@app.get("/items/")
async def read_items(
    hidden_query: Annotated[str | None, Query(include_in_schema=False)] = None,
):
    if hidden_query:
        return {"hidden_query": hidden_query}
    else:
        return {"hidden_query": "Not found"}
```

`hidden_query` 不会出现在生成的 OpenAPI schema（以及基于它的自动文档）里，但客户端传了它照样生效，适合"内部参数、不对外公开"的场景

## Part 8 自定义校验声明

内置规则（`min_length`、`max_length`、`pattern`……）总有力所不能及的时候。比如"ID 必须以 `isbn-` 或 `imdb-` 开头"这种业务规则，内置参数表达不了，就需要**自定义校验函数**：在常规校验（比如先确认是字符串）之后，跑一遍自己写的函数。FastAPI 用 Pydantic 的 `AfterValidator` 实现，把校验函数放进 `Annotated` 里即可：

```python
import random
from typing import Annotated

from fastapi import FastAPI
from pydantic import AfterValidator

app = FastAPI()

data = {
    "isbn-9781529046137": "The Hitchhiker's Guide to the Galaxy",
    "imdb-tt0371724": "The Hitchhiker's Guide to the Galaxy",
    "isbn-9781439512982": "Isaac Asimov: The Complete Stories, Vol. 2",
}


def check_valid_id(id: str):
    if not id.startswith(("isbn-", "imdb-")):
        raise ValueError('Invalid ID format, it must start with "isbn-" or "imdb-"')
    return id


@app.get("/items/")
async def read_items(
    id: Annotated[str | None, AfterValidator(check_valid_id)] = None,
):
    if id:
        item = data.get(id)
    else:
        id, item = random.choice(list(data.items()))
    return {"id": id, "name": item}
```

拆开看：

- `check_valid_id(id: str)` 是自定义校验函数：校验不通过就 `raise ValueError`，通过就原样返回
- `AfterValidator(check_valid_id)` 把函数放进 `Annotated`，FastAPI 会在常规校验之后调用它，校验失败同样返回 422
- 示例里如果用户没传 `id`，`data.items()` 取出（键，值）对，`random.choice` 随机挑一条作为建议返回——一行内联就把"取随机项"做完了

两个边界要记住：**这种自定义校验只适合"凭请求数据本身就能判断"的规则**；如果校验要查数据库或调别的 API，应该用后面章节的 FastAPI Dependencies（依赖注入），自定义校验不负责这类活。另外 `AfterValidator` 是 Pydantic 2 及以上的能力，Pydantic 也提供 `BeforeValidator`（校验前运行）等其他选择。自定义校验与内置规则可以并存：内置的 `min_length`、`max_length`、`pattern` 管"常规约束"，自己写的函数管"业务规则"，各司其职

## 小结

| 概念      | 一句话                                                       |
| ------- | --------------------------------------------------------- |
| 额外校验   | `Query(min_length=... / max_length=... / pattern=...)` 给字符串参数加长度与正则约束   |
| Annotated | 新写法 `Annotated[str \| None, Query(...)] = None`：校验进注解、默认值留原位；旧写法是 `Query` 当默认值，需手动 `default=` |
| 默认值与必填 | 带默认值（含 `None`）可选；不写默认值必填；类型允许 `None` 但无默认值 = "必填但可空" |
| 多值参数   | `list[str]` + `Query()` 把重复参数收集成列表；不写 `Query` 会被当作请求体 |
| 元数据    | `title`、`description` 进 OpenAPI，给文档和工具看，不影响校验逻辑        |
| 别名     | `alias` 决定 URL 参数名，Python 变量名可以不同（`item-query` → `q`）   |
| 弃用与排除 | `deprecated=True` 在文档里标注弃用；`include_in_schema=False` 从 OpenAPI 排除 |
| 自定义校验 | `AfterValidator` + 自写函数放进 `Annotated`，在常规校验后追加业务规则         |

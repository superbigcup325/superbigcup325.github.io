前面在[《Rust 入门：所有权》](<2026-07-27-Rust-入门：所有权.md>)里学过引用与借用：引用不夺取所有权，让代码在不移动数据的前提下使用它。但引用必须始终指向「仍然有效」的数据，这一章讲的生命周期就是 Rust 用来保证这件事的机制

## Part 1 生命周期是什么：引用有效的范围

Rust 中**每个引用都有生命周期（lifetime）**——引用保持有效的那个作用域范围

> 注：可以把生命周期想成「引用合法存续的时间段」。这是绝大多数其他编程语言都没有的概念，所以刚开始会觉得陌生，但后面会看到它正是 Rust 保证内存安全的关键一环

生命周期的作用场景很明确：**确保引用在我们需要的期间内始终有效**。讲泛型时说过，泛型约束类型的「行为」；而生命周期是另一类泛型：泛型类型参数保证「类型有我们要的行为」，生命周期保证「引用在我们需要期间内有效」

和类型推断一样，**大多数时候生命周期是隐式的、由编译器推断的**，就像大多数时候类型不用手写。我们只在「多种可能」时标注：类型有多种可能时标注类型；当引用的生命周期可能以几种不同方式相互关联时，就必须标注生命周期。Rust 中用**泛型生命周期参数**来标注这些关系，确保运行时实际使用的引用一定有效

### 1.1 概念速记

| 概念 | 一句话 |
| --- | --- |
| 生命周期 | 引用有效的范围，每个引用都有 |
| 泛型生命周期参数 | 让函数接受任意生命周期的引用，并描述引用之间的关系 |
| 何时需要标注 | 多个引用的生命周期有多种可能的关联方式时 |

## Part 2 主要目的：防止悬垂引用

生命周期机制的主要目的，是**防止悬垂引用（dangling reference）**。悬垂引用就是我们常说的「野指针」：引用已经不再有效的数据。如果允许它存在，程序就会引用到意图之外的数据。看下面这个例子，外层作用域里声明了 `r`，内层作用域里把 `r` 指向局部变量 `x`：

```rust
fn main() {
    let r;

    {
        let x = 5;
        r = &x;
    }

    println!("r: {}", r);
}
```

这段代码编译不过，因为 `r` 引用的 `x` 在内层作用域结束时就已经离开了作用域。报错信息写着 `x` does not live long enough（活不够久）：

```
$ cargo run
error[E0597]: `x` does not live long enough
  --> src/main.rs:6:13
   |
5  |         let x = 5;
   |             - binding `x` declared here
6  |         r = &x;
   |             ^^ borrowed value does not live long enough
7  |     }
   |     - `x` dropped here while still borrowed
9  |     println!("r: {r}");
   |                   - borrow later used here
```

`x` 的作用域比 `r` 小，`r`「活得更久」。如果 Rust 允许这段代码运行，`r` 就会指向 `x` 离开作用域后被释放的内存，之后对 `r` 的任何操作都是错的

### 2.1 借用检查器：用作用域大小判断有效性

Rust 编译器里有一个 **借用检查器（borrow checker）**，它比较作用域的大小，判断所有借用是否有效。把上面代码的各个生命周期画出来看：

```rust
fn main() {
    let r;                // ---------+-- 'a
                          //          |
    {                     //          |
        let x = 5;        // -+-- 'b  |
        r = &x;           //  |       |
    }                     // -+       |
                          //          |
    println!("r: {r}");   //          |
}                         // ---------+
```

`r` 的生命周期标为 `'a`，`x` 的生命周期标为 `'b`。可以看到内层的 `'b` 块比外层的 `'a` 块小得多。编译时 Rust 比较两个生命周期的大小，发现 `r` 的生命周期是 `'a`、指向的数据却只有 `'b`，**引用指向的数据没有引用本身活得久**，程序被拒绝

把声明顺序调换，让数据活得更久就编译通过了：

```rust
fn main() {
    let x = 5;
    let r = &x;
    println!("r: {r}");
}
```

这里 `x` 的生命周期比 `r` 大，`r` 在 `x` 有效期间始终有效

> 补充：上面的例子里 `r` 声明时没有初始值，看起来和「Rust 没有 null」矛盾。其实 Rust 会拒绝在赋值之前使用变量——一旦尝试就会编译报错，Rust 里根本没有 null 值可用

## Part 3 函数中的泛型生命周期

这是一个返回两个字符串切片中较长者的 `longest` 函数：

```rust
fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest(string1.as_str(), string2);
    println!("The longest string is {result}");
}

fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}
```

（这里传的是切片引用而不是 `String` 本身，因为我们不想让函数接管参数的所有权，这正是[所有权](<2026-07-27-Rust-入门：所有权.md>)中讲字符串切片做参数的原因）

这段代码编译不过，报错 missing lifetime specifier：

```
$ cargo run
error[E0106]: missing lifetime specifier
  --> src/main.rs:9:33
   |
9  | fn longest(x: &str, y: &str) -> &str {
   |               ----     ----     ^ expected named lifetime parameter
   |
   = help: this function's return type contains a borrowed value, but the signature does not say whether it is borrowed from `x` or `y`
```

帮助信息说得很清楚：返回类型里含借用值，但签名没说它是从 `x` 借的还是从 `y` 借的

关键难点在于：定义函数时我们不知道调用时会传入哪些具体值，也不知道传入引用的具体生命周期，所以没法像上面画作用域那样判断返回值是否始终有效。借用检查器同样判断不了，因为它不知道 `x`、`y` 的生命周期和返回值的生命周期有什么关系。解决办法就是添加**泛型生命周期参数**来定义引用之间的关系，让借用检查器能完成分析

### 3.1 生命周期注解语法

生命周期注解不改变任何引用的实际存活时间，只描述多个引用的生命周期之间的关系。就像函数签名用泛型类型参数接受任意类型，泛型生命周期参数让函数接受任意生命周期的引用

注解语法有点特别：生命周期参数名必须以撇号 `'` 开头，通常全小写、很短，惯例第一个用 `'a`。注解写在引用的 `&` 之后、类型之前，用空格隔开：

```rust
&i32        // 一个引用
&'a i32     // 带显式生命周期 'a 的引用
&'a mut i32 // 带显式生命周期 'a 的可变引用
```

单独一个注解没有多少意义，注解的用途是告诉 Rust 多个引用的生命周期参数之间**如何关联**

### 3.2 在函数签名里声明生命周期参数

在函数签名中使用生命周期注解，要在函数名和参数列表之间的尖括号里声明泛型生命周期参数，和泛型类型参数一样。我们希望签名表达这样的约束：**返回的引用，在两个参数都有效期间内有效**。把生命周期命名为 `'a`，加到每个引用上：

```rust
fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest(string1.as_str(), string2);
    println!("The longest string is {result}");
}

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

这个签名告诉 Rust：对于某个生命周期 `'a`，函数接收两个至少活到 `'a` 的字符串切片，返回的切片也至少活到 `'a`。实际含义是：**返回引用的生命周期，等于两个参数生命周期中较小的那个**

记住一点：在签名里指定生命周期参数，并不是改变传入值或返回值的生命周期，而是规定**借用检查器要拒绝任何不符合这些约束的值**。`longest` 也不需要知道 `x`、`y` 具体活多久，只需要存在某个作用域能代入 `'a` 满足签名

注解只写在函数签名里，不写在函数体里。生命周期注解是函数契约的一部分，就像签名里的类型一样。编译器基于签名做分析，一旦标注或调用有问题，错误能精确定位到出错的代码和约束，而不是离问题十万八千里外的调用点

### 3.3 使用实例：不同生命周期的引用

给 `longest` 传入不同具体生命周期的引用，看看注解如何约束它：

```rust
fn main() {
    let string1 = String::from("long string is long");

    {
        let string2 = String::from("xyz");
        let result = longest(string1.as_str(), string2.as_str());
        println!("The longest string is {result}");
    }
}

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

`string1` 有效到外层作用域末尾，`string2` 只到内层作用域末尾，`result` 引用到内层末尾前都有效。借用检查器批准，编译通过，打印 `The longest string is long string is long`

再把 `result` 的声明移到内层作用域外面、使用移到内层结束后：

```rust
fn main() {
    let string1 = String::from("long string is long");
    let result;
    {
        let string2 = String::from("xyz");
        result = longest(string1.as_str(), string2.as_str());
    }
    println!("The longest string is {result}");
}

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

编译失败，报错 `string2` does not live long enough。因为签名里 `'a` 取两个参数中较小的生命周期，想让 `result` 在 `println!` 时有效，`string2` 就得活到外层作用域末尾，但它在内层就被丢弃了

> 注：即使函数实际返回的是较长生命周期的 `string1` 的引用，由于我们签名中的生命周期参数要求了两个传入的参数都是存活的，所以在 `string1` 释放后，会直接拒绝

### 3.4 不同实现需要不同的注解

函数具体做什么，决定需要标注哪些生命周期。如果把 `longest` 改成总是返回第一个参数，就不用给 `y` 标注了：

```rust
fn longest<'a>(x: &'a str, y: &str) -> &'a str {
    x
}
```

`y` 的生命周期和 `x`、返回值都没有关系，自然不用标注

反之，如果返回的引用**不指向任何参数**，就只能指向函数内部创建的值——而函数结束时该值会离开作用域被清理，就成了悬垂引用，Rust 不会允许：

```rust
fn longest<'a>(x: &str, y: &str) -> &'a str {
    let result = String::from("really long string");
    result.as_str()
}
```

编译失败，报错 cannot return value referencing local variable `result`。无论指定什么生命周期参数都无法挽救，因为 `result` 在函数结束时就被清理了。正确的修法是**返回拥有所有权的类型**（比如直接返回 `String`），由调用方负责清理

## Part 4 struct 中的生命周期注解

到目前为止我们定义的 struct 都持有拥有所有权的类型。也可以定义**持有引用的 struct**，但那样就得给 struct 定义里的每个引用加生命周期注解：

```rust
struct ImportantExcerpt<'a> {
    part: &'a str,
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let i = ImportantExcerpt {
        part: first_sentence,
    };
}
```

这个 struct 只有一个字段 `part`，持有一个字符串切片（即引用）。和泛型数据类型一样，生命周期参数名写在 struct 名后的尖括号里，以便在 struct 定义体里使用。这个注解的含义是：**`ImportantExcerpt` 的实例不能比它在 `part` 字段里持有的引用活得更久**

上面 `main` 里，`novel` 在 `ImportantExcerpt` 实例创建之前就已存在，又比实例晚离开作用域，所以实例里的引用始终有效

## Part 5 省略规则：为什么之前的函数不用标注

到这里可能会问：既然每个引用都有生命周期，为什么前面学过的 `first_word` 这种函数（参数是引用、返回值也是引用）在编译时却完全不用标注？

```rust
fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }

    &s[..]
}
```

原因带着点历史色彩：Rust 早期版本（1.0 之前）里每个引用都必须显式写生命周期，上面的签名当时要写成 `fn first_word<'a>(s: &'a str) -> &'a str`。Rust 团队写了大量代码后发现，程序员在特定场景下一遍遍重复输入相同的生命周期注解，而这些场景可预测、有规律。于是这些模式被编进编译器的代码，让借用检查器在这些场景下自己推断生命周期。这些模式就叫**生命周期省略规则（lifetime elision rules）**

省略规则**不是**给程序员遵守的规则，而是编译器会考虑的一组特定情形，当你的代码符合这些情形，就不用手写生命周期。但要注意：省略规则**不做完整推断**。如果应用完规则后引用仍有歧义，编译器不会猜，而是直接报错，让你补上生命周期注解

### 5.1 输入生命周期与输出生命周期

先明确术语：

- 函数或方法**参数**上的生命周期叫**输入生命周期（input lifetimes）**
- **返回值**上的生命周期叫**输出生命周期（output lifetimes）**

### 5.2 三条省略规则

编译器在没有显式注解时，用下面三条规则确定引用生命周期。三条规则同样适用于 `fn` 定义和 `impl` 块，按顺序应用：

| 规则 | 适用对象 | 内容 |
| --- | --- | --- |
| 第一条 | 输入 | 为每个输入类型中的每个生命周期，各分配一个不同的生命周期参数。如 `fn foo(x: &i32, y: &i32)` 会得到 `fn foo<'a, 'b>(x: &'a i32, y: &'b i32)` |
| 第二条 | 输出 | 如果恰好只有一个输入生命周期参数，把它赋给所有输出生命周期参数：`fn foo<'a>(x: &'a i32) -> &'a i32` |
| 第三条 | 输出 | 如果有多个输入生命周期参数，但其中一个因为这是方法而写成了 `&self` 或 `&mut self`，那么 `self` 的生命周期赋给所有输出生命周期参数 |

三条规则走完，仍有引用确定不了生命周期，编译器就报错

### 5.3 拿规则走一遍

假装自己是编译器，对 `first_word` 的签名应用规则：

```rust
fn first_word(s: &str) -> &str {           // 初始签名
fn first_word<'a>(s: &'a str) -> &str {    // 应用规则一：每个参数一个生命周期
fn first_word<'a>(s: &'a str) -> &'a str { // 应用规则二：唯一输入赋给输出
```

规则二恰好适用，所有引用的生命周期都确定了，编译器继续分析，不需要程序员标注

再看 `longest` 当初的签名：

```rust
fn longest(x: &str, y: &str) -> &str {         // 初始签名
fn longest<'a, 'b>(x: &'a str, y: &'b str) -> &str { // 应用规则一：两个参数两个生命周期
```

第二条规则不适用（不止一个输入生命周期），第三条规则也不适用（`longest` 是函数不是方法，没有 `self` 参数）。三条规则走完，返回类型的生命周期仍然未知——这就是当初编译 `longest` 报错的原因：编译器走完省略规则，还是确定不了签名里所有引用的生命周期

## Part 6 方法定义中的生命周期注解

在带生命周期的 struct 上实现方法，语法和泛型类型参数一致。struct 字段的生命周期名**必须在 `impl` 关键字后声明**，再在 struct 名后使用——因为这些生命周期是 struct 类型的一部分。方法签名里的引用，可能关联到字段引用的生命周期，也可能与之无关，而省略规则通常让方法签名不用标注。看 `ImportantExcerpt` 上的两个方法：

```rust
struct ImportantExcerpt<'a> {
    part: &'a str,
}

impl<'a> ImportantExcerpt<'a> {
    fn level(&self) -> i32 {
        3
    }
}

impl<'a> ImportantExcerpt<'a> {
    fn announce_and_return_part(&self, announcement: &str) -> &str {
        println!("Attention please: {announcement}");
        self.part
    }
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let i = ImportantExcerpt {
        part: first_sentence,
    };
}
```

`impl<'a>` 后的生命周期声明和 struct 名后的使用是必须的；但 `level` 唯一参数是 `&self`、返回值 `i32` 不是引用，应用第一条规则即可，不用标注 `self` 引用的生命周期

`announce_and_return_part` 则是第三条规则生效的典型：有两个输入生命周期（`&self` 和 `announcement`），第一条规则给它们各分配一个，又因为其中一个是 `&self`，返回类型取 `self` 的生命周期，所有生命周期都确定了。正是这条规则让方法签名少了很多符号，好读好写

## Part 7 静态生命周期 'static

还有一个特殊生命周期 `'static`，表示被标记的引用**可以活到整个程序的运行期间**。所有字符串字面量都有 `'static` 生命周期，可以这样标注：

```rust
let s: &'static str = "I have a static lifetime.";
```

字符串字面量的文本直接存在程序的二进制文件里，始终可用，所以它们的生命周期是 `'static`

> 补充：错误信息里经常出现「建议用 `'static`」的提示。但动手把生命周期改成 `'static` 之前，先想清楚：你手里的引用真的会活满整个程序吗？你希望它这样吗？大多数情况下，这种建议源于悬垂引用或可用生命周期不匹配，正确的解法是修掉这些问题，而不是把生命周期强标成 `'static`

## Part 8 把生命周期、泛型与 trait bound 放在一起

生命周期本质上是泛型的一种，所以生命周期参数和泛型类型参数可以写在同一组尖括号里，再配合 trait bound。这是三类内容的最终合体：

```rust
use std::fmt::Display;

fn longest_with_an_announcement<'a, T>(
    x: &'a str,
    y: &'a str,
    ann: T,
) -> &'a str
where
    T: Display,
{
    println!("Announcement! {ann}");
    if x.len() > y.len() { x } else { y }
}

fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest_with_an_announcement(
        string1.as_str(),
        string2,
        "Today is someone's birthday!",
    );
    println!("The longest string is {result}");
}
```

和 `longest` 相比多了个泛型类型 `T` 的参数 `ann`，`where` 子句约束 `T` 必须实现 `Display`——因为函数体里要用 `{}` 打印它。生命周期参数 `'a` 和泛型类型参数 `T` 声明在同一个尖括号列表里

## 小结

| 概念 | 一句话 |
| --- | --- |
| 生命周期 | 引用有效的范围，每个引用都有；保证引用在需要期间有效 |
| 泛型生命周期参数 | 让函数接受任意生命周期的引用，描述引用间关系 |
| 悬垂引用 | 指向已释放数据的引用（野指针），生命周期机制要防止的 |
| 借用检查器 | 比较作用域大小判断借用是否有效的编译器组件 |
| 注解语法 | `&'a i32`、`&'a mut i32`，`'a` 写在 `&` 后、类型前，以 `'` 开头 |
| 函数签名注解 | `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`，注解只在签名不在函数体 |
| 返回引用约束 | 返回值生命周期必须关联某个参数；不能返回函数内部创建的引用，应返回拥有所有权的类型 |
| struct 注解 | `struct ImportantExcerpt<'a> { part: &'a str }`，实例不能比持有的引用活得更久 |
| 输入/输出生命周期 | 参数上的叫输入生命周期，返回值上的叫输出生命周期 |
| 三条省略规则 | 每个输入一个生命周期；唯一输入赋给所有输出；方法 `self` 赋给所有输出 |
| 省略规则的边界 | 规则走完仍不确定就报错，不会猜 |
| 方法注解 | `impl<'a> ImportantExcerpt<'a>`，字段生命周期在 `impl` 后声明 |
| `'static` | 能活到程序结束的生命周期，字符串字面量默认就有；错误建议用时要先想清楚 |

`generics` 示例覆盖了 Rust 泛型的完整语法：函数、struct、enum、方法里的泛型，多泛型参数，以及单态化与性能。所有编程语言都有处理「概念重复」的工具，Rust 的工具之一就是**泛型（generics）**：作为具体类型或其他属性的**抽象替身**，我们可以在不知道编译和运行时是什么类型的情况下，写出泛型的行为以及它们之间的关系

## Part 1 为什么要泛型：消除重复代码

### 1.1 从抽取函数开始

先看一个找最大数的程序：

```rust
fn main() {
    let number_list = vec![34, 50, 25, 100, 65];

    let mut largest = &number_list[0];

    for number in &number_list {
        if number > largest {
            largest = number;
        }
    }

    println!("The largest number is {largest}");
    assert_eq!(*largest, 100);
}
```

把列表存进 `number_list`，用 `largest` 引用第一个数，然后遍历整个列表，遇到更大的数就替换引用，最后 `largest` 指向最大数（这里是 100）。如果现在有两个列表都要找最大数，把这份代码复制两份也能跑，但**复制代码很繁琐、还容易出错**，并且以后想修改时，还得记得同时改多处

要消除重复，就把这段逻辑抽象成一个函数，参数是任意整数列表：

```rust
fn largest(list: &[i32]) -> &i32 {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let number_list = vec![34, 50, 25, 100, 65];

    let result = largest(&number_list);
    println!("The largest number is {result}");
    assert_eq!(*result, 100);

    let number_list = vec![102, 34, 6000, 89, 54, 2, 43, 8];

    let result = largest(&number_list);
    println!("The largest number is {result}");
    assert_eq!(*result, 6000);
}
```

`list` 参数代表任意具体的 `i32` 切片。抽取有三步：

1. 识别重复代码
2. 把重复代码提取进函数体，在函数签名中声明输入和返回值
3. 把两处重复的代码改成调用函数

### 1.2 从抽取值到抽取类型

同样的思路可以应用到类型上：函数体可以操作抽象的 `list` 而不是具体的值，泛型则允许代码操作**抽象的类型**。假如有两个函数，一个在 `&[i32]` 里找最大数，一个在 `&[char]` 里找最大数，函数体完全一样，只是类型不同：

```rust
fn largest_i32(list: &[i32]) -> &i32 {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn largest_char(list: &[char]) -> &char {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}
```

函数体一模一样，重复的只有类型，就能用接下来讲的泛型合并成一个函数

## Part 2 函数中的泛型

在函数签名中原先写具体类型参数和返回值类型的位置放上泛型，代码就更灵活、给调用方更多功能，同时避免重复。合并后的 `largest` 函数：

```rust
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let number_list = vec![34, 50, 25, 100, 65];

    let result = largest(&number_list);
    println!("The largest number is {result}");
    assert_eq!(*result, 100);

    let char_list = vec!['y', 'm', 'a', 'q'];

    let result = largest(&char_list);
    println!("The largest char is {result}");
    assert_eq!(*result, 'y');
}
```

- 读法：「函数 `largest` 对某种类型 `T` 是泛型的」——参数 `list` 是 `T` 的切片，返回值是 `T` 的引用
- `T` 是**类型参数**的名字。Rust 惯例是类型参数名要短（通常一个字母），并遵守 UpperCamelCase 命名规范；`T` 是 type 的缩写，是大多数 Rust 程序员的选择
- 类型参数声明放在**函数名和参数列表之间的尖括号 `<>`** 里
- 和值参数一样，在函数签名里用了类型参数名，就必须先声明它

### 2.1 为什么必须写 T: PartialOrd

如果只写 `fn largest<T>(list: &[T]) -> &T`，编译会报错：

```
error[E0369]: binary operation `>` cannot be applied to type `&T`
```

原因在于：当 `largest` 接收 `&[T]` 时，函数对 `T` 的类型不确定。但 `largest` 要求 `T` 能用 `>` 比较，也就是 `T` 实现了 `PartialOrd` trait。有的类型可以比较（如 `i32`、`String`），有的不行（如 `File`）。`T: PartialOrd` 叫 **trait bound（trait 约束）**，是对泛型类型能力的**提前声明**；trait bound 的具体语法属于 trait 主题，这里先会用即可

Rust 与 C++ 模板的区别：C++ 编译器不会在定义 `largest` 时报错，而是在你拿 `&[File]` 调用它时才报错；Rust 要求在定义时就声明泛型类型具备的能力。Rust 也没有 Java 那种「所有对象都有一组核心方法（如 `toString`）」——不加约束的泛型类型 `T` **没有任何能力**：不能打印、不能克隆、不能修改（但可以被 drop）

## Part 3 struct 中的泛型

struct 也能用 `<>` 语法在字段里使用泛型类型参数。`Point<T>` 保存任意类型的 `x`、`y` 坐标：

```rust
struct Point<T> {
    x: T,
    y: T,
}

fn main() {
    let integer = Point { x: 5, y: 10 };
    let float = Point { x: 1.0, y: 4.0 };
}
```

用法和函数定义相似：在 struct 名后紧跟尖括号声明类型参数，再在字段类型的位置使用泛型

**注意：`Point<T>` 只用了一个泛型参数，所以 `x` 和 `y` 必须是同一个类型**。写成 `Point { x: 5, y: 4.0 }` 会编译报错（E0308）：当 `x` 赋整数 `5` 时，编译器已经确定这个实例的 `T` 是整数，`y` 的 `4.0` 与之矛盾。想让 `x`、`y` 类型可以不同，就要用多个泛型参数（见 Part 4）

### 3.1 泛型 enum：Option<T> 与 Result<T, E>

enum 同样可以持有泛型数据。标准库的 `Option<T>` 就是泛型 enum：

```rust
enum Option<T> {
    Some(T),
    None,
}
```

`Option<T>` 对类型 `T` 泛型，有两个变体：`Some` 携带一个 `T` 值，`None` 不携带任何值。用它可以表达「可选值」这个抽象概念，并且因为 `Option<T>` 是泛型的，无论可选值的具体类型是什么都能用

`Result` 则是多泛型参数的 enum：

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

`Ok` 携带成功的值 `T`，`Err` 携带失败的错误 `E`。回顾第 9 章打开文件的例子：成功时 `T` 是 `std::fs::File`，失败时 `E` 是 `std::io::Error`。**当你发现多个 struct 或 enum 定义只是持有值的类型不同时，就用泛型消除重复**

## Part 4 多个泛型类型参数

想让 `Point` 的 `x`、`y` 类型可以不同，用两个泛型参数：

```rust
struct Point<T, U> {
    x: T,
    y: U,
}

fn main() {
    let both_integer = Point { x: 5, y: 10 };
    let both_float = Point { x: 1.0, y: 4.0 };
    let integer_and_float = Point { x: 5, y: 4.0 };
}
```

三种实例全部合法。一个定义里可以放任意多个泛型参数，但**超过几个就会让代码难以阅读**；如果发现自己需要很多泛型参数，可能是代码需要重构、拆成更小的部分

## Part 5 方法中的泛型

方法定义里同样能使用泛型。在 `Point<T>` 上实现一个返回 `x` 字段引用的方法：

```rust
struct Point<T> {
    x: T,
    y: T,
}

impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}

fn main() {
    let p = Point { x: 5, y: 10 };

    println!("p.x = {}", p.x());
}
```

注意 `impl` 后面也要声明 `T`（`impl<T>`），这样 Rust 才能识别 `Point` 尖括号里的是泛型类型而不是具体类型。`impl` 里的泛型参数名可以和 struct 定义里的不同，但保持一致是惯例。**在 `impl` 块声明了泛型类型后，该方法对任何实例都可用，不管实际替换成什么具体类型**

### 5.1 只对具体类型实现方法：impl Point<f32>

也可以只对某个具体类型实现方法。比如只给 `Point<f32>` 一个计算到原点距离的方法，此时 `impl` 后不声明泛型：

```rust
impl Point<f32> {
    fn distance_from_origin(&self) -> f32 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}
```

这样只有 `Point<f32>` 有 `distance_from_origin`，其他 `Point<T>`（`T` 不是 `f32`）没有，因为距离计算用到了只有浮点类型才有的数学运算

### 5.2 泛型方法不能与具体类型方法同名

**不能同时为同一个方法名实现泛型版本和具体类型版本**。比如既给所有 `T` 实现通用的 `distance_from_origin`，又给 `f32` 实现具体的 `distance_from_origin`，编译器会拒绝：当调用 `Point<f32>::distance_from_origin` 时，Rust 不知道该用哪个实现。更一般地说，Rust 没有面向对象语言里那种继承式的**方法特化（specialization）**机制

### 5.3 方法里的泛型参数可以不同于 struct 的

struct 定义里的泛型参数与方法签名里的不一定相同。`mixup` 方法用 `X2`、`Y2` 接收另一个 `Point`，生成一个混搭的 `Point`：

```rust
struct Point<X1, Y1> {
    x: X1,
    y: Y1,
}

impl<X1, Y1> Point<X1, Y1> {
    fn mixup<X2, Y2>(self, other: Point<X2, Y2>) -> Point<X1, Y2> {
        Point {
            x: self.x,
            y: other.y,
        }
    }
}

fn main() {
    let p1 = Point { x: 5, y: 10.4 };
    let p2 = Point { x: "Hello", y: 'c' };

    let p3 = p1.mixup(p2);

    println!("p3.x = {}, p3.y = {}", p3.x, p3.y);
}
```

`p3` 的 `x` 来自 `p1`（`i32`），`y` 来自 `p2`（`char`），打印出 `p3.x = 5, p3.y = c`。要点：`X1`、`Y1` 声明在 `impl` 后，因为它们属于 struct 定义；`X2`、`Y2` 声明在 `fn mixup` 后，因为它们只属于这个方法

## Part 6 单态化：泛型零运行时开销

用了泛型，程序会不会变慢？好消息是：**用泛型不会比用具体类型慢**。Rust 在编译期对泛型代码做**单态化（monomorphization）**

即把泛型代码通过填入实际用到的具体类型，转成具体代码。编译器做的就是我们在 Part 1 反向做的步骤：找出所有调用泛型代码的地方，为调用时用到的每种具体类型分别生成一份代码

以标准库的 `Option<T>` 为例：

```rust
let integer = Some(5);
let float = Some(5.0);
```

编译时，编译器读取实例化 `Option<T>` 时用到的值，识别出两种 `Option<T>`：`i32` 和 `f64`，于是把泛型定义展开成两份专门化的定义，大致等价于：

```rust
enum Option_i32 {
    Some(i32),
    None,
}

enum Option_f64 {
    Some(f64),
    None,
}

fn main() {
    let integer = Option_i32::Some(5);
    let float = Option_f64::Some(5.0);
}
```

（实际编译器用的名字与此不同，这里只是为了说明。）因为 Rust 把泛型代码编译成了指定具体类型的代码，**用泛型没有任何运行时开销**。运行时的表现和手写每一份重复定义一模一样。单态化让 Rust 的泛型在运行时极其高效

## 小结

| 概念                          | 一句话                                                       |
| ----------------------------- | ------------------------------------------------------------ |
| 泛型                          | 具体类型或其他属性的抽象替身，用来消除概念重复               |
| 消除重复三步                  | 识别重复 → 抽取进函数并声明签名 → 替换调用点                 |
| `fn largest<T>(list: &[T])`   | 函数泛型语法，`T` 声明在函数名和参数列表之间的 `<>` 里       |
| `T: PartialOrd`               | trait bound，声明泛型类型必须具有 `>` 比较能力               |
| `struct Point<T>`             | struct 泛型，`x`、`y` 必须是同一个类型（同一个 `T`）         |
| `Option<T>` / `Result<T, E>`  | 泛型 enum，`Some(T)` / `None`，`Ok(T)` / `Err(E)`            |
| `Point<T, U>`                 | 多泛型参数，字段类型可以不同；太多会让代码难以阅读           |
| `impl<T> Point<T>`            | `impl` 后声明泛型，方法对所有实例可用                        |
| `impl Point<f32>`             | 只对具体类型实现方法，`impl` 后不声明泛型                    |
| 同名冲突                      | 不能同时实现泛型版和具体类型版的同名字方法                   |
| `mixup<X2, Y2>`               | 方法级泛型参数，独立于 struct 级泛型参数                     |
| 单态化                        | 编译期把泛型展开成具体类型，运行时零开销                     |

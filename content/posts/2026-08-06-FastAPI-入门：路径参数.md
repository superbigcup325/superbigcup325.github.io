上一篇文章中，示例接口`@app.get("/")` 的路径是写死的；但真实接口通常要按资源取数——`/users/123` 里的 `123`、`/items/foo` 里的 `foo`，这类**随请求变化、嵌在 URL 路径里的值**，就是接下来要讲的：**路径参数（path parameter）**。本篇讲清楚四件事：怎么声明、FastAPI 为什么能自动校验、声明顺序为什么有讲究、以及 Enum 和"参数本身就是路径"这两个进阶处理方式

## Part 1 路径参数：把 URL 里的值取出来

沿用 Python 格式化字符串的语法，在路径里用 `{参数名}` 占位，就能声明一个路径参数：

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/items/{item_id}")
async def read_item(item_id):
    return {"item_id": item_id}
```

关键就在 `{item_id}`：请求 `/items/foo` 时，路径里的 `foo` 会作为参数 `item_id` 传进函数。浏览器打开 http://127.0.0.1:8000/items/foo 会看到：

```json
{"item_id":"foo"}
```

把这段代码拆开看：

| 部分                 | 作用                                        |
| ------------------ | ----------------------------------------- |
| `/items/{item_id}` | 路径操作里的路径，`{item_id}` 是参数占位符            |
| `item_id`          | 路径操作函数接收的参数，名字与占位符一致                     |
| `{"item_id": item_id}` | 返回一个 dict，把收到的参数原样回给客户端               |

至此一切都在"字符串的世界"里：URL 本来就是文本，`foo` 进函数时是一个字符串

## Part 2 类型声明：自动转换（parsing）

只声明参数名还不够，加上 Python 标准类型注解，FastAPI 就有了"魔法"：

```python
@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}
```

这回 `item_id` 被声明成 `int`。访问 http://127.0.0.1:8000/items/3，返回：

```json
{"item_id":3}
```

注意细节：返回的 `3` 是 Python 的整数，不是字符串 `"3"`。这一行类型声明，让 FastAPI 替你做了**数据解析（parsing）**——把 HTTP 请求里拿到的字符串，按声明的类型转成 Python 数据。这个过程也叫**序列化 / 反序列化 / 数据转换**，叫法不同，指的都是同一件事

顺带一个收益：类型声明后，函数内部写代码时，编辑器知道 `item_id` 是 `int`，自动补全和类型检查都能用

## Part 3 数据校验：Pydantic 说了算

如果请求的是 http://127.0.0.1:8000/items/foo 呢？`foo` 转不成整数。FastAPI 不会默默出错，而是返回一个标准化的 HTTP 422 校验错误：

```json
{
  "detail": [
    {
      "type": "int_parsing",
      "loc": ["path", "item_id"],
      "msg": "Input should be a valid integer, unable to parse string as an integer",
      "input": "foo"
    }
  ]
}
```

传 `4.2` 也一样——`float` 转不成 `int`，同样报错。这份错误信息很有用：`loc` 精确指出了出错的**位置**（在路径 `item_id` 这个参数上），`input` 是你传入的原始值，`type` 是错误类型。开发调试对接 API 时，这份明确性价值巨大

> 补充：这个校验错误是 **422 Unprocessable Entity** 状态码，HTTP 语义是"请求格式对、但内容校验不过"。上篇说过 4xx 是客户端错误，422 是其中一个细分

这套校验背后是 **Pydantic**——FastAPI 的所有数据校验都由它完成。你写类型声明，Pydantic 负责按声明校验和转换，`str`、`float`、`bool` 乃至更复杂的数据类型都支持。上篇说过"FastAPI 基于 Pydantic"，这里是第一次真正用上它：

| 概念           | 一句话                                 | 谁来做                              |
| ------------ | ---------------------------------- | -------------------------------- |
| 数据解析（parsing） | HTTP 字符串 → Python 数据                 | FastAPI + Pydantic，按你的类型声明        |
| 数据校验（validation） | 转不过去就返回标准错误                          | Pydantic                          |
| 文档           | 类型声明自动反映到 docs 页面                    | FastAPI 根据 OpenAPI 规范自动生成        |

打开 http://127.0.0.1:8000/docs，会发现路径参数那一栏里 `item_id` 的类型已标成 integer；`/redoc` 同样会自动更新。**没有多写一行文档代码，一切来自那一个类型注解**

## Part 4 声明顺序决定匹配顺序

假设要同时支持两个路径：`/users/me`（查当前用户）和 `/users/{user_id}`（按 ID 查用户）。直觉上写在一起，但**顺序必须小心**：

```python
@app.get("/users/me")
async def read_user_me():
    return {"user_id": "the current user"}


@app.get("/users/{user_id}")
async def read_user(user_id: str):
    return {"user_id": user_id}
```

路径操作是**按声明顺序逐个匹配**的。`/users/me` 必须先声明：请求 `/users/me` 时，FastAPI 从上往下找，先命中写死的 `/users/me`。如果调换顺序、把 `/users/{user_id}` 放前面，那么 `/users/me` 也会被它"吞掉"——FastAPI 会以为 `user_id` 的值就是 `"me"`：

| 声明顺序                          | `/users/me` 的实际结果        |
| ----------------------------- | ----------------------- |
| `/users/me` 在前、`/users/{user_id}` 在后 | 命中"当前用户"接口，行为正确       |
| `/users/{user_id}` 在前          | `"me"` 被当成 user_id，行为错误 |

同理，同一个路径**不能重复声明**。写两个 `@app.get("/users")`，只有先声明的那一个会被用到，后一个永远匹配不上：

```python
@app.get("/users")
async def read_users():
    return ["Rick", "Morty"]


@app.get("/users")
async def read_users2():
    return ["Bean", "Elfo"]
```

访问 `/users` 永远返回第一个的 `["Rick", "Morty"]`。记住一句话：**写死的固定路径放在前面，带参数的放在后面，同一个路径别写两遍**

## Part 5 用 Enum 预定义取值

有的路径参数只接受几个固定值。比如按模型名查询，只有 `alexnet`、`resnet`、`lenet` 三个合法值。用 Python 标准库的 `Enum` 就能把"合法取值"写死在类型里：

```python
from enum import Enum
from fastapi import FastAPI

class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"

app = FastAPI()

@app.get("/models/{model_name}")
async def get_model(model_name: ModelName):
    if model_name is ModelName.alexnet:
        return {"model_name": model_name, "message": "Deep Learning FTW!"}

    if model_name.value == "lenet":
        return {"model_name": model_name, "message": "LeCNN all the images"}

    return {"model_name": model_name, "message": "Have some residuals"}
```

拆开看这个用法：

| 要点                      | 说明                                            |
| ----------------------- | --------------------------------------------- |
| `class ModelName(str, Enum)` | 同时继承 `str` 和 `Enum`：文档能识别取值是字符串，渲染正常      |
| 类属性 = 合法取值            | `alexnet = "alexnet"` 这类固定值就是允许传入的路径值      |
| `model_name: ModelName`   | 路径参数声明成枚举类型，传入的值必须是枚举成员之一                |
| `model_name is ModelName.alexnet` | 拿枚举成员直接做身份比较                                  |
| `model_name.value`        | 取出实际的字符串值，如 `ModelName.lenet.value` 得到 `"lenet"` |
| 返回枚举成员                 | 会先被转成对应的值（字符串）再发给客户端                      |

访问 http://127.0.0.1:8000/models/alexnet，返回：

```json
{"model_name": "alexnet", "message": "Deep Learning FTW!"}
```

响应里的 `model_name` 是字符串 `"alexnet"`——枚举成员在返回前被自动转换了。传一个非法值比如 `/models/foo`，会得到 422 校验错误；而 docs 页面会把三个可选值漂亮地列出来，前端对接时一看就知道有哪些选择。三个模型名分别是不同的深度学习网络架构，这里只是借名举例

> 补充：`model_name` 这个枚举写法里有两个分支判断，`is` 和 `== value` 两种比较方式各示范一次，是 Pydantic/枚举混用的常见小抄；实际判断只用一种风格即可

## Part 6 参数里再嵌路径：path convertor

有时路径参数本身还要"含路径"。比如想表示文件 `/files/home/johndoe/myfile.txt`，其中 `file_path` 的值是 `home/johndoe/myfile.txt` 这样一整段带斜杠的路径。

问题在于：**OpenAPI 规范不支持声明"参数里含路径"**——这种写法难以测试和定义。但 FastAPI 可以绕过：借用底层 **Starlette**（FastAPI 基于它构建）提供的一个选项，在参数名后加 `:path`：

```python
@app.get("/files/{file_path:path}")
async def read_file(file_path: str):
    return {"file_path": file_path}
```

`{file_path:path}` 里的 `file_path` 是参数名，`path` 是**路径转换器（path convertor）**，告诉 FastAPI 这个参数要匹配任何路径（含斜杠）。访问：

```text
/files/home/johndoe/myfile.txt
```

返回：

```json
{"file_path": "home/johndoe/myfile.txt"}
```

如果参数值本身要以 `/` 开头（比如 `/home/johndoe/myfile.txt`），URL 里要写双斜杠 `/files//home/johndoe/myfile.txt`。副作用是：docs 页面不会提示这个参数应包含路径——OpenAPI 不支持，文档只能缺这块说明，功能本身不受影响

## 小结

| 概念              | 一句话                                                                 |
| --------------- | ------------------------------------------------------------------- |
| 路径参数            | URL 路径里的可变值，用 `{item_id}` 声明，值会作为参数传进函数                          |
| 类型注解            | 给参数加 `: int` 等类型，FastAPI 自动做字符串→Python 数据的解析                     |
| 数据校验            | 转不过去返回 422 错误，包含出错位置（`loc`）与原始值（`input`）；背后是 Pydantic            |
| 文档联动            | 类型声明自动反映到 `/docs`、`/redoc`，无需手写文档                                   |
| 声明顺序            | 路径操作按顺序匹配：固定路径写前面，参数化路径写后面；同一路径别重复声明                          |
| Enum 预定义取值       | 继承 `str, Enum` 的枚举类限定合法取值；可 `is` 比较、用 `.value` 取值、返回时自动转字符串      |
| 参数含路径            | 用 Starlette 的 path 转换器 `{file_path:path}`；OpenAPI 文档不声明、但功能可用        |

对照上篇的[《HTTP 协议》篇](<2026-08-05-计算机网络基础：HTTP-协议.md>)看：路径参数本质上是**资源标识的一部分**——`/users/me` 是"当前用户"这个资源，`/users/{user_id}` 是"某个 ID 的用户"这个资源，REST 的"用 URL 表达资源"在 FastAPI 里就是这么落到实处的

> 补充（概念澄清）：路径参数与查询参数的分工——`/users/{user_id}` 里的 `user_id` 是**路径参数**，标识"哪个资源"；`?page=1` 是**查询参数**，表达"资源的筛选与分页"等附加条件。下一篇《查询参数》会专门展开
